# 格式化已有流程图（入口 B）

> 第一段（读材料·落表）判定为入口 B 时读取。目标：把已有的一张图，重建成《流程表》，再渲染为本 SKILL 的统一风格。
> **转换完成后，流程表成为新的事实源，原图不再维护。**

## 1. 三种来源与可行路径

| 来源 | 路径 | 自动化程度 |
|---|---|---|
| 本 SKILL 生成的 `.drawio` | `sync.py` 一键同步：名称与走向可全自动读回，语义列以《流程表》为准 | 全自动 |
| 其他工具画的 `.drawio` / `.xml` | `xml_reader.py` 直接读回：`<mxCell vertex="1">` 按 style 判形状、按入/出边定起止，坐标推断 row/col | 全自动（语义留空） |
| 图片 / 白板照片 / PDF / 截图 | AI 视觉识别节点与连线 → 填流程表 | 人工 |

外部图的读回规则（`xml_reader.py` 已实现）：

- **类型**：`rhombus`=判断；胶囊（`arcSize≥40`）或 `ellipse` 是**端点符**——无入边=开始、无出边=结束，
  入边全是回环也判为开始，否则任务；其余=任务
- **标签**：取 `value`，自动剥 HTML；`<br>` 转空格
- **节点名称**：取**框内可见文字的第一行**。框内第二、三行是执行者/行动所需时间，**都不回读**——
  多行重排后无法可靠区分"第二行是执行者"还是"用户把名称写成了两行"，要改它们请改《流程表》。
  自家产物更彻底：图里根本不写语义属性（D-73），所以属性面板里没有可改的语义
- **连线**：`source`/`target` 定连接，`value` 为分支标签，`dashed=1` 记为虚线（negative）
- **几何**：读 `mxGeometry`，按中心坐标聚类推断 `row`/`col` 与列中心 `col_x`，**并排分支与多列结构能还原**
- **装饰元素**：`style="text;…"` 的标题/图例自动跳过，不进流程表
- **语义字段**：输入/依据/输出/主体/执行者/时间/描述在原图里不存在 → 留空，回写时以 `-` / `—` 占位，由 AI 补全并以 `⚠` 标出（图上虚线）

## 2. 操作步骤

```bash
# ① 读回并看懂：拓扑摘要（一行一节点，判断节点缩进列出各分支）
python flowchart-skill/scripts/xml_reader.py "原图.drawio"

# ② 若已有流程表，先看差异
python flowchart-skill/scripts/xml_reader.py "原图.drawio" --diff "output/<名称>/flowtable.md"

# ③ 一键同步：读回 → 差异 → 回写流程表 → 生成 DSL（带二维布局）→ 质量门禁
python flowchart-skill/scripts/sync.py "原图.drawio" "output/<名称>/flowtable.md"
```

首次导入没有流程表时，先 `init.py <名称>` 建目录（空骨架只保留表头与项目元信息），再跑第 ③ 步；确认差异后加 `--apply` 覆盖并重渲染。

### 回写的三条保真规则

回写 diff 是用户 `--apply` 前**唯一的把关界面**。一旦掺进"没动过的行也变了"的伪差异，人就会学会忽略 diff，真正的语义漂移反而漏过去。所以 `writeback.py` 按最小差异原则写：

1. **分支顺序来自原文，不按编号排**——`(分支标签 + 目标编号)` 与原文一致的边**逐字回填原 token**，作者写的次序（主路径/通过分支在前）原样保住；只有新增/改动的边才生成新文本。
2. **编号后的自由注解与「回」标记一并不动**——`回 10 重编`、`回 26 继续积累` 这类注解在解析期就不进 DSL，只能从原文逐字取回；「回」是给人看的可读标记、不参与判定，不由工具重猜。
3. **换行符与 BOM 随原文件**——必须看**字节**判断（`read_text` 的通用换行会把 CRLF 归一成 LF，按文本判断会永远判成 LF），写回时 `newline=''` 关掉 Windows 的 `\n`→`\r\n` 翻译。否则原文是 LF 时整份文件都会显示为改动。

> 判据是 `(label, tid)` 配对：在 drawio 里改了标签或换了目标，该分支就按新内容重写；删了边，该 token 消失。**没碰过的分支，回写后一字不差。**

## 3. 补齐语义（外部图必做）

读回后 `xml_reader` 会提示"缺主体/执行者的节点 N 个"。AI 须：

1. 结合原图上下文（泳道名、节点措辞、图例配色）**推断**每个节点的执行主体与执行者
2. 推断出的内容在该节点「节点描述」以 `⚠` 开头写明依据（图上虚线标注，用户看图即见）
3. 时限、依据条款原图通常没有 → 留 `—`；能按上下文推出来的补上并以 `⚠` 标出
4. 补充完成后重跑结构校验，再渲染

## 4. "统一风格"具体指什么

| 维度 | 统一后的表现 |
|---|---|
| 形状 | 胶囊=起止 / 菱形=判断 / 圆角矩形=任务，同类型等尺寸、行中线对齐 |
| 配色 | 按「执行主体」映射（`dictionary.yaml` 或 DSL `meta.subjects`） |
| 文字 | 名称粗体 + 执行者灰小字 + 行动所需时间橙粗字 |
| 连线 | 主干实线、回路虚线走左侧通道、长跳走右通道，边永不穿节点 |
| 标签 | 分支标签居中压线，白底徽章 |
| 详情 | 悬浮显示输入/依据/输出/主体/执行者/时间/上游/下个节点/描述 |
| 产物 | `output/<名称>/` 下的 flowtable.md / <流程名>-flow.yaml / <流程名>-flow.html / <流程名>-flow.drawio |

## 5. 防呆

- 原图缺失的语义**不要编造**：推断出的内容一律以 `⚠` 标出，让用户在图上看得见
- 原图节点粒度过粗（一个框代表一个阶段）→ 拆成多个任务节点；拆分依据拿不准的以 `⚠` 标出
- 原图有跨页/子流程 → 用 `项目运作阶段` 列分组，必要时拆成子 SOP（见 `drawio-loop.md`）
- 原图的排版信息（绝对位置、颜色偏好）**不保留**，几何由布局引擎按 row/col 重算
- 质量门禁报"边穿过节点" → 只调 `<流程名>-flow.yaml` 的几何字段（`row`/`col`/`gutter`/`channel`/`dye`），或调原图后重新同步
