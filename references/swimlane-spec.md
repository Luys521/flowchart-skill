# 泳道布局（输出布局 = 泳道）

> 当要表达「**谁在哪个阶段做什么**」——多个部门在同一流程里分工协作时读取。
> 流程布局（默认）表达"先后"，泳道布局表达"分工 × 阶段"。两者是**同一份流程表的两种输出**。

## 1. 什么时候用

| 想表达 | 用哪种 |
|---|---|
| 一件事分几步、每步谁做、在哪分支 | **流程布局**（默认） |
| 多部门协作：每个阶段有哪些部门参与、各自做什么 | **泳道布局** |

判据：如果"部门"是读者要横向比较的维度（谁先动、谁在等谁），就该用泳道。

## 2. 怎么开启

流程表正文的「## 渲染配置」小节表里声明：

```markdown
## 渲染配置

| 键 | 值 |
| --- | --- |
| 输出布局 | 泳道 |
| 泳道列序 | 代理商 → 解决方案中心 → 户用业务中心 → 资方 → 采购管理部 → 财务部 → 智慧运维中心 |
```

只认「泳道」二字：含"泳道"即泳道布局，否则流程布局。落到 DSL 里是 `meta.layout: swimlane`。

**两个轴都从流程表现有列自动取**，不需要新填任何东西：

| 轴 | 来源列 | 顺序 |
|---|---|---|
| **行** | 项目运作阶段 | 未声明列序时：按首次出现（即表的流程顺序）；**声明了列序**：改按流程槽位（见 §3.1） |
| **列** | 执行主体 | 有「泳道列序」就按它；没有才按首次出现 |

同一阶段的多部门节点会自动落到同一行、不同列。横向**不再表示先后**——先后由连线表达。

### 2.1 「泳道列序」：什么时候要写

**写了就同时开启槽位模式**（§3.1），所以它不是纯样式选项。两种情况下该写：

1. **列序不是首次出现顺序**——最典型的是白板/合作协议里已经画定了部门左右次序，或者首现顺序读起来别扭
2. **有全空的泳道**（如某个部门在本流程里不参与，但你要把这一列画出来）——空列没有节点去认领，
   只能靠显式列序占位；顺序照单全收，不受"谁先出现在表里"摆布

分隔符用 `→`（也兼容 `,` `，` `、`）。列名必须与「执行主体」列一字不差，否则该列会被当成新泳道、
凭空多出一列空泳道。

**列序怎么定**（不是靠手感）：把「列序」当自变量，定义

```text
Φ(列序) = |{ 边 u→v : stage(u) == stage(v) 且 col(v) ≤ col(u) }|      # 同阶段逆行边数
K = 阶段数 + Φ                                                        # 槽位数
```

求使 Φ 最小的列序（`≤8` 条泳道直接穷举），即得槽位最少的排法。两条已知的结构下界——同泳道的先后边
与跨泳道的业务回退——决定了 Φ 不可能降到 0，所以**最小 K 就是验收基准**：跑出更小的 K 说明槽位规则被改坏了。
细节与槽位规则见本文件 §3.1。

> **最小 K ≠ 业务最优。** K 少意味着更多节点被压进同一行；若业务上要求两个部门"先后分明"，
> 宁可多占一槽。所以自动求解结果只作**建议**，由你写进「泳道列序」定稿。

## 3. 格位与尺寸

- 同一 (槽位 × 部门) 格有多个节点时**纵向堆叠**，按表的先后
- 列宽 = 该列最宽的节点 + 2×`lane.pad`
- 尺寸只要求**四边落粗格**。流程布局那条 `h ≡ 20 (mod 40)` 是"共用行中线"的副产品
  （`y = 中线 − h/2` 要落格）；泳道不共用中线，所以 160×60 原样保留、不会被抬到 80
- 格内**摞顶**按该格**最严的形状**定刻度：格里有矩形类节点 → 吸粗格 20（它四边守粗格）；整格都是
  非矩形（菱形）→ 只吸细格 10。一律吸粗格会把纯菱形格推下 10px：行中线恒为 `20k+10`，而
  `160×80` 菱形 `摞高/2 = 40 ≡ 0 (mod 20)` ⇒ 摞顶必落在 `20k+10`，永远吸不上粗格（D-33）

### 3.1 槽位模式（声明了「泳道列序」时生效）

**问题**：一个阶段往往含多个先后步骤（"备货"下面有申请、审核、发货、签收、启动五步）。
若一行 = 一个阶段，该阶段的节点只能在一格里纵向摞成一摞，行高被撑大，其他列只有一个节点就被
**悬在行正中**——中心的 y 根本落不到行线上。

**做法**：行从「阶段」细化为「流程槽位」，层高改**严格等距** `lane.pitch`。

```text
slot(v) = max over 入边 (u→v) of:
              slot(u)          若 stage 相同 且 col(v) > col(u) 且 同槽里没有夹在两列之间的节点  # 向右交棒 → 同槽
              slot(u) + 1      其他                                                              # 推进一槽
起始节点 slot = 0
```

- 用 `max` 而非顺序递推 → 天然处理分支/汇聚（多入边取最深的那条）
- **向右交棒还得"中间没人"**：同槽里若已站着夹在两列之间的节点，合并会让这条边横跨它
  （`17→18` 跨过 `16a`：图上只能贴着框绕，还与别的线交叉）→ 另开一槽（D-36）
- 图含回路时拓扑序取不到 → 退回按表序推导，并在输出里留一条提示
- 分支可能跳过某个槽号 → 空槽会被压缩掉，层数才是真实层数
- 层中线必须落在 `20k+10`（矩形四边守粗格），`pitch = 120` 时行顶余数取 `10 − pitch/2 (mod 20)`；
  这个余数**与阶段行模式不同**，且随标题带开关翻转，所以按当前 `legend_h` 现算

**左轴（阶段色带）随之改成合并绘制**：一个阶段横跨多行时必须合并成一条色带，否则左侧会叠出一串
同名小色块。渲染层读 `lanes()['stage_spans']`（连续同阶段的行区间）。

**没声明「泳道列序」的表行为一字不变**——槽位模式与阶段行模式是同一份代码的两条分支。

## 4. 连线

- 端口按**源与目标的相对位置**选：目标在下 → 下进上出；在上 → 上进下出；同行 → 左右。
  写死"下进上出"会让"目标在上"的边一出门就折回源节点内部（validate 第 4 项会报"横穿自身节点"）
- **首段与末段的方向都必须 = 端口法线方向**（D-17/D-27）：对向端口（下→上 / 左→右 等）且两轴都有偏移时
  走 **Z 形**（中段在两锚点之间折一次）——此时的 L 形必有一端贴着节点边沿（如水平段贴目标上边框、
  箭头横着顶进顶口），几何门禁查不出来（源/目标自身被豁免），只能靠形状规则避免
- 同行跨列的长线若会穿过中间列的节点，自动改走**本行上/下空带**绕行——行高按格内内容算，空带本就存在
- 回环走两者左边之外
- 门禁与流程布局**完全一致**（八项），泳道不是"免检区"，尤其"边不穿节点""边不重叠"照查

## 5. 参数（`scripts/dictionary.yaml` 的 `lane` 段）

| 参数 | 默认 | 作用 |
|---|---|---|
| `head` | 60 | 顶部「职能部门」带高 |
| `stage` | 120 | 左侧「里程碑阶段」带宽 |
| `pad` | 60 | 每列左右留白 |
| `vpad` | 40 | 每行上下留白（仅阶段行模式） |
| `gap` | 40 | 同格相邻节点间距；一律吸附到 `20 + 40k`（D-16：多节点格的摞高须与单节点格同余，否则行内各列中线差 10px），默认 40 实际生效 60，被吸附时门禁输出（`· 网格吸附:`）会留提示 |
| `pitch` | 120 | 槽位模式的等距层高 = 节点高 60 + 净空 60 |
| `route_left` | 0 | 左侧里程碑带之外的路由走廊**下限**（粗格）。宽度由引擎**探布量出**：先按旧口径布一趟，看有几条线真落进带里，就按条数把走廊留到带右边再重解（D-39）。这里填值只会把走廊抬得比量出来的更宽。**跨趟只还布线器自己写下的东西**：端口、`dye`、挪到空闲侧的端口，以及自动设下的错峰 `sdye`（手填的两种都不动，见 D-31 / D-82） |

### 5.1 底色绘制：必须铺满（D-41）

四件事缺一不可——部门列起点 = `stage_w + route_left`（与节点列对齐，**不是**从 `stage_w` 起）、
末列铺到画布右沿、阶段带纵向从表头底画到画布底、左侧走廊那一条补同色底。
任一条漏了，图上就会出现"底图没铺满"：白边、或者末列节点探出底色。
产物侧门禁会量底色的外包盒，**节点落在底色之外即报错**。

## 6. 取舍（说清楚，别当成缺陷）

- **横向不表示先后**。"更靠左"只意味着"更早被表提到"或"被你写在「泳道列序」更前"，不意味着"先执行"。要读先后请顺着连线走。
- **阶段/部门的列序**：没声明「泳道列序」时 = 首次出现顺序（想调整就改流程表的行序）；
  声明了就按声明来（见 §2.1）。
- 节点多而部门少时泳道会显得稀疏——那是信息本身如此，不是布局问题。
- 部门配色沿用主体配色（同 `meta.subjects`），所以**背景列色 = 该部门的颜色**，不必逐个读节点。
