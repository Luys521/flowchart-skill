# 视觉规范与布局引擎

> 需要解释配色/形状/布局规则，或产物不合预期需排查时读取。

## 0. 网格规范（一切几何的底座）

**两级刻度**：节点盒用粗格 20，线走细格 10。矩形盒的直边错半格看得出来，菱形的斜边错 10px 肉眼无感——所以让直边更严，让夹缝里的线更松。

| 层级 | 刻度 | 约束对象 | 落盘位置 |
|---|---|---|---|
| 细格 `grid.lattice` | 10 的倍数 | 全部折点、通道 x、通道间距、`dye` 错位量、标签徽章四边、画布高 | 推导量，不落盘 |
| 粗格 `grid.node` | 20 的倍数 | **矩形类节点**（任务/子流程）四边、画布宽、`col_x` | `layout.col_x` |

**形状即格位**：菱形、胶囊一律先归一成外接矩形（`shapes.<type>.size` 就是它的格位），布局器、布线器、校验器只认这个矩形，形状只决定"墨迹"（胶囊的左右半圆就是墨迹，见 D-74）。所以加新形状不需要动布局，只需在 `shapes` 里注册形状名并给出格位尺寸。

**由此推出的尺寸约束**（`geometry.fit_size` 会自动吸附，改字典时知道边界即可）：

| 形状类 | 判据 | 可取值 | 例 |
|---|---|---|---|
| 矩形类 | `shape: rounded/stadium` | w 取 40 的倍数、h 取 20 mod 40 → **只能 60/100/140** | 任务 160×60 ✓ / 起止 160×60 ✓ / 160×80 ✗ |
| 非矩形 | `shape: rhombus` | w、h 取 20 的倍数 | 判断 160×80 ✓ |

推导：所有节点共用行中线（中线落在 `20k+10`），节点 `x = col_x − w/2`、`y = 中线 − h/2`。
要四边落粗格 ⇒ `w/2`、`h/2` 也得是粗格倍数。共中线 + 高度 60/80 两者不可能同时落 20 格，
这就是判断节点保持在 80（守细格）而任务守粗格的原因——不是妥协，是"直边严、斜边松"的取舍。

**唯一出口**：吸附只在 `geometry.py` 做（`snap` / `ceil_to` / `fit_size`），router 与 label 只做细格吸附。
下游渲染器不取整。`validate.py` 第 8 项复检，兜住绕过几何层的代码路径。

## 0.1 主轴 · 臂 · 就近（三条可量的审美律）

图读得快不快，先看**墨迹怎么铺**。三条规律，一条比一条具体，每条都有仪器能量（`dev/tools/aesthetic.py`）：

| 律 | 一句话 | 量什么 | 阈值 |
|---|---|---|---|
| **主轴** | 主链（同一列里前后相接的那一串）是整张图的轴，图绕它对称铺开 | `主轴偏心 = |主轴 x − 墨迹外包盒中心 x| / 墨迹宽` | ≤ 0.15 |
| **臂** | 同一层的分支分挂主轴**两侧**，不许全堆一侧 | 同上——偏心就是"两臂不均衡"的直接读数 | ≤ 0.15 |
| **就近** | 每条边走两端之间最短的正交路径；非绕不可时**贴着最近那一列的外沿**走，多条并行走线**紧凑成束**（细格 10 的整数倍），一侧放不下再向另一侧分 | `绕行率 = (折线实长 − 两端锚点曼哈顿距离) / 曼哈顿距离` | 均值 ≤ 35% · 最坏 ≤ 50% |

**为什么"就近"才是可泛化的那条**：绕行不该是为避让付的代价。原实现的通道族位置**写死在"最右列中心 + 140、束距 60"**上——
一条只跨两行的跳转边也得先跑到全图最外圈再折回来。把基准改成"本边涉及列的**最外沿** + 40"（贴列）、束距 60→50：
自举 33 张表平均绕行 **52% → 42%**、workflow 树 **9% → 7%**，`validate` 逐张全过（依据见 D-91）。

**束距有下界，而它不是偏好**：标签盒宽 40px，束内两条边各挂一个标签时，间距小于"标签宽 + 一格"就必然重叠——
实测束距 40/20、回路束距 20 都会让 `render_html` 那类表报「标签互相重叠」。所以 50 是这条律与「标签不许重叠」
两条规则的交点；想再挤，得先让标签自己会错位（那是 labeler 的活，不是调参）。
**「臂」已落地**（D-92）：`flowtable_layout.balance_arms` 把并行分支按**墨迹重量**贪心分挂主轴两侧
（主轴 = 「开始」那一列；列数与列距不动，只换"哪个节点坐哪一列"；列数 <3 时不动，单列产物逐字节不变），
左族的基准也随之下沉到"**本边涉及列的左沿**"（旧左廊降级为末位兜底——它靠的正是"主轴恒为最左列"，
前提一破，回路就得绕过整条左臂：实测 `05f→05b` 绕行 385%）。实测 workflow 树两张侧支表：
主轴偏心 **0.43 → 0.00**、绕行 7%/7% → **3%/6%**、画布 1340 → 1160。
**单臂表（只有一条分支列）配不平**——没有两侧可分，工具标「单臂」且不进偏心均值。
**"长跳束分两侧"试过两次都更差**（自举 42%→45%、43%→45%）：那一侧的长跳竖直跨度互相重叠，谁也用不了
谁的竖道，束宽是"条数 × 束距"的硬账；要降得让**跨度**变短（生成器把长跳拆两列），记在 `coding-spec` G12。
门⑨ 已按"当前收口值"钉住（偏心 ≤0.15 · 通道半径 ≤0.5 · 绕行均值 ≤45%、最坏 ≤60%），退化即红。

**"臂"这一条目前只做到一半**：`flowtable_layout` 的列号是「`col` = 0 单主列，并行侧支拿 `col` ≥ 1」，
所以主列永远是最左那一列——侧支表的偏心 0.37~0.43 是结构后果，不是路由问题。要真正做到"两臂分列主轴两侧"，
得让并行分支能分到主列左边（`col` 允许负值；router 本就有左/右两族通道，接口够）。

## 1. 一个视觉通道只承载一个语义维度

| 语义维度 | 视觉通道 | 规则 |
|---|---|---|
| 节点类型 | 形状 | 胶囊=起止 / 菱形=判断 / 圆角矩形=任务；同类型等尺寸，行中线对齐 |
| 执行主体 | 填充色+边框 | `meta.subjects` 配置映射（对应流程表「执行主体」） |
| 执行者 | 灰色小字 | 节点内第二行 |
| 行动所需时间 | 橙色粗字 | 节点内第三行（有则显示） |
| 分支极性 | 实线/虚线 | 通过=实、不通过+回路=虚；标签不带编号 |
| 完整详情 | 悬浮 | 输入/依据/输出/主体/执行者/时间/上游/下个节点/描述 |
| 主干边上的流光 | 悬停时的两层光 | 只在悬停节点时跑、鼠标离开即停（D-80）；**悬停配对用节点的 `data-nid`（DSL 原始编号）与边的 `data-from/to`**——子视图里 `data-id` 带 `视图key::` 前缀，拿它比永远不相等（D-90） |
| 箭头与滤镜的定义 | 文档级资源 | 单文件多视图的 html 里**只许一份、且在全部视图之外、之后**（`<svg class="vdefs">`）：`url(#…)` 按 id 解析，落在视图里的那份会随该视图 `display:none` 一起失效（D-90） |
| 子 SOP | **节点内一道内衬线**（同形状内缩 2px / 1px / 55%） | 描述含 `⊞ 路径` 的节点 → 框内一道细线（永远在，静态可见，**不带任何动画**）；悬浮框在**节点名右侧**一行灰字提示「（点击查看流程详情）」；HTML 单击**切到内嵌的子图视图**、drawio `Ctrl+点击`跳同文件子页 |
| **AI 推断** | **两档虚线描边** | 「节点描述」以 `⚠` 开头 → `pending.stroke` 橙 + 疏虚线；以 `⚠?` 开头 → `pending.verdict` **红 + 密虚线**。两档不能画成同一款：`⚠` 是"AI 有依据、你不必管"，`⚠?` 是"必须你拍板"；只靠颜色分不出的是色弱用户，所以虚线节奏也分开 |

**上表每一行三份产物都要画**（D-86）：节点三行文字（名称 / 执行者 / 行动所需时间）、`⚠` 两档虚线、
边标签、内衬线——**html / drawio / svg 一个不缺**。交付物③（svg）是"朴素可编辑中间态"，
"朴素"指的是没有交互与动画，**不是内容可以少**：单独把它发出去，判断节点分出"是 / 否"两支却看不出
分支条件、`⚠` 那几处看不出要核对，等于这份产物读不全。
**圆角以 drawio 的 `arcSize`（占短边的百分比）为准**：drawio 原样写 `arcSize=6`，html/svg 按
`min(w,h)×arc/100` 换算成 `rx`（160×60 ⇒ 3.6px）——同一个数不能一边当百分比、一边当像素。

**「AI 推断」这一维度的意义**：本 SKILL 是「高级 mermaid」——AI 独立提炼与渲染，**用户只对最终渲染图负责**，
不会去读 `checklist.md` 这类中间产物。所以"哪里没底"必须画在图上才有用。虚线节点 = 请重点核对这里。
用户改完（或确认无误）后，把描述里的 `⚠` 去掉再 `build.py` 重渲染，虚线即消失。

**为什么"可下钻"必须另开一个通道，而不是复用描边**：上表七行就是七个已占满的通道。
`⚠` 已经吃掉了**节点描边**，`悬浮` 吃掉了交互提示——若把 `⊞` 也画成描边，
"这处推断存疑"与"这里有子流程"就再也分不开。

**一条铁律：记号必须落在节点包围盒内。** 出框的记号会同时和**端口**、**相邻墨迹**、**包围盒/网格**打交道，
而且每一种都在别的模块里（布线、碰撞、布局），改一处必漏一处。下面几个候选就是按这条被逐个淘汰的。

**为什么不用别的记号**（三种形状——矩形 / 菱形 / 胶囊——上逐个试过）：

| 候选 | 为什么不采用 |
|---|---|
| 右上角一个 `⊞` 角标 / 右下折角 / 右上页签 | **出框**，而且只能贴在**直角包围盒**的角上——菱形、胶囊上会飘出形状（包围盒的四角在形状之外） |
| 节点外圈的流动虚线环 | 出框 + 借「运动」这个通道，只在**屏幕上**成立：截图、打印、单发的 HTML 里几乎看不见；还把「虚线」这一维又借了一次（`⚠` 已在用） |
| 向外叠的背卡（同形状、向右下偏移 5/10px） | 出框：**端口在外接矩形的边中点上**，向下的出线与向右的出线会从卡片里钻出来；外扩 10px 的包围盒 170×70 还是**离格**的 |
| **采用：框内一道内衬线** | 同形状、**内缩 2px**、**描边 1px**、**同色 55%**——谁都不碰：端口干净、连线口径不变、包围盒与网格不动；跟着形状走（菱形内缩一圈菱形），**静态可见** |

**内衬线规格**：内缩 `SUB_INSET = 2.0`、`stroke-width:1`、同色 55% 不透明（三份产物同值），
**无填充**、**不带虚线**（`⚠` 是节点的事，不是它的）。规格收到这么细，是因为节点高 60、
文字两到三行时内圈离文字只剩几像素——只有退成"里衬"才不跟文字抢。

- **为什么在框内**：见上面那条铁律。附带好处：菱形的内圈顺手补上了形状本身的信息。
- **为什么静态、而且只有这一层**：记号的本分是"看得见"——截图、打印、`prefers-reduced-motion` 下都得在。
  曾经悬停时另跑一段光沿它转一圈，撤掉了（D-80）：那是"连线上已经在跑的那道流光"的第二遍，
  而"这里能点"本来就该由**悬浮框**说——用户已经伸手去点的那一刻说，最省事也最准。
  所以"能点"落在悬浮框标题行右侧一行灰字 `（点击查看流程详情）`，判据与内衬线、下钻入口**同一个**
  （真的把子图内嵌进来了才有；声明了 `⊞` 但那张表拿不到 DSL 的，三样一起不出现）。
- **图例里不解释它**：记号说不出"子流程"四个字，解释它的那句话就是悬浮框里那句提示（见上一条）——
  标题栏只放"这是什么图 / 颜色是谁"（见下文「图例」）。
- 游标只在可下钻节点上是 `pointer`（`cursor:default` 的节点点了没反应，与"看起来能点"必须一致）。

**悬停反馈只加不减**：悬停节点自己的描边加粗（`.ndg:hover .shape`），相关主干边**在悬停期间循环**跑流光
（鼠标离开即停）。**不压暗任何东西**——压暗会把别的节点上的 `⚠` 描边、主体配色、执行者小字一起抹掉，
那是删信息；而且"哪些是相关的"已经有加法记号，不必再来一遍减法（D-76）。

**相关边不加粗**（D-80）：边上的光已经在回答"哪儿相关"，加粗是同一个意思说第二遍，也让线宽口径
（实线 2 / 虚线 2 + 短划）平白多出一个例外。加粗这一半如今只剩**悬停节点自己**那一圈，它是静态的——
系统要求「减少动态效果」时流光不画，这一圈仍在，悬停反馈不会整个消失。

**流光 = 两层同一道光**（`晕` + `芯`，见 D-79）：晕 = 宽 9 + `feGaussianBlur 2.5` + `stroke-opacity .4`，
芯 = 宽 3 + 实 + 同色系加深一档，走流光的蓝（`#4a86c8` / `#2f6fb4`）。**它只出现在连线上**——
内衬线保持静态（D-80），一份产物里只留一处会动的东西。

- **"中间很亮、周围渐变"是叠出来的，不是渐变**：折线拐弯处沿路径的渐变跟不上（那要按路径算渐变），
  而两层段只要共用同一套 `dash` 与时长，就自然成"一道光"。
- **一律不用白色**：白只在**深色**底上发光——开源实现里 `svg-flow` 的默认轨道是 `#1a1a2e`、ECharts 的飞线配深色地图；
  我们的底是白画布与浅色填充，白在那儿只能"把线擦亮"，读作擦除而不是发光。
- **晕的透明度写 `stroke-opacity`**：动画动的是 `opacity`，写 `opacity` 会连晕一起点满，"渐变"就没了。
- **循环只活在悬停期间**（D-80）：一触发只跑一趟是一闪而过，像页面抖了一下，读不出"光顺着流程
  一条条走下去"；常驻循环又会把"实线/虚线"这条作者语义磨掉，也看不出这束光是在回答"我现在看着谁"。
  所以循环由悬停开关：一圈 1.6s，相邻流程步之间再错峰 120ms——错峰是"顺着流程走"的全部来源。

**叠影只画在"子图真的内嵌进来了"的节点上**：`⊞` 声明了但那张子表拿不到可用 DSL 的，不画叠影、不给入口。
理由和"虚线只在有 `⚠` 时画"一样——**画上去就要有用**，一个点下去没反应的入口比不画还糟。

### 单文件多视图（D-52）

主 html 是**一个文件**：全部后代子图内嵌在里面，各占一个 `<div class="view">`，点可下钻节点是切视图
（`display` 切换）而不是改 `location`。发给客户就发那一个文件——子目录丢了也不会 404。

- **图例只有一份**，取**跨层并集**：主图与所有内嵌子图用到的主体都要能查到颜色。
  同一个主体跨层两色是**硬错误**（阻断渲染），这是 D-49 那条"颜色即身份"的跨层版
- **标题随视图换**：`<h1>` 由脚本改成当前视图的标题；图例不动
- **面包屑由脚本维护**：下钻后左上角出现轨迹（`主图 › 子图`），点其中一截即可回去；
  顶层不摆空条（没有回程路就不显示）
- **无子图时输出与从前逐字节相同**：没有后代子图就不进入多视图分支，老产物一份都不用重生成

### 下钻回来要停在原处（视窗位置记忆）

下钻是为了"按需展开"，不是"从头再来"。**切回某一层时必须把视窗恢复到离开前的位置**
（`window.scrollX/Y` + `.chart-container` 的 `scrollLeft/Top`，存 `sessionStorage`，
键 = `location.pathname` + **视图 key**——单文件里路径不再区分层级，必须带上视图）。
否则大图里每次返回都被扔回左上角，用户"刚才看到哪儿了"这个上下文就丢了——
那这个功能用起来比不做还累：省下的滚动量，全在回程里赔回去。

两个实现细节：**恢复必须在 `fitHead()` 之后**（布局还没定时滚动会滚到错的位置）；
`scroll` 事件要节流（200ms）并配 `beforeunload` 兜底，否则快速跳转时最后一段位移会丢。

**图例只回答两件事：这是什么图（标题）、颜色是谁（主体色块行，按 `meta.subjects` 生成）**。
形状（胶囊/菱形/矩形）、线型（实线/虚线）、橙色字都能一眼看出，写进图例只是噪声；
**用法说明也不写**（曾经有一句「悬浮节点查看路由与描述」）：它常驻在标题栏里却说的是要动手才知道的事，
而 drawio 版没有悬浮语义、这句话在那边本就不成立——两版图例因此逐字一致，只有一个真值。
图例为空（未配主体）时只留标题。

### 标题模块与正文模块（两个模块）

页面分**两块**，标题、图例色块**合成一个标题模块**：

| 模块 | 内容 | 版式 |
|---|---|---|
| 标题模块 | 图表标题 + 主体色块行 | HTML：画布**外**的固定条，滚动时不离视窗 |
| 正文模块 | 流程图本体（SVG 画布） | 随滚动移动 |

- **HTML 版**：标题模块 `position: fixed` 钉在视窗顶部，正文让出它的高度（脚本按实际高度回填 `padding-top`）。
  图再长，"这是什么图 / 颜色是谁"也始终在眼前。
- **drawio 版**：没有"视窗外"这回事，同一块内容画在画布顶部的 `legend_band` 预留带内
  （标题与图例**同一个 cell**，拆开会互相拖错位）；`origin_y` 已按带宽下推，带内不可能有节点或折点。
- 两版只差一个顶部偏移量（`legend_band`），节点之间的相对位置完全一致。
  因此 HTML 渲染时调 `L.head_band(False)` 关掉画布预留——那一段留白改由画布外的标题模块占据。

## 2. 渲染管线（脚本全自动）

| # | 阶段 | 做什么 |
|---|---|---|
| 1 | 节点类型分析 | 按流程表「节点类型」列映射形状，同类型等尺寸、行中线对齐 |
| 2 | 节点关系分析 | 解析「下个节点」为有向边，识别主干 / 分支 / 回环，定实线虚线与极性 |
| 3 | 空间规划 | 拓扑分层定 row/col；主干带标签 → 满间距 140px，无标签 → 缩至 100px。流程布局的列**由算法给出**：汇聚到同一点的分支并排占相邻列、腾空的层压掉（D-37）；列间距走 `layout.col_pitch` |
| 4 | 节点连接 | **前向对角（下行跨列）先走干净 L**（右下=右出顶入、左下=底出右入，两段都沿端口法线、一个折点、不占节点左右端口，D-28）；L 走不通再按通道族布线：跨相邻列的边走列间空隙（Z 形）／单列回路走左侧通道／长跳走右侧通道。分配通道时**同时避让节点、已占通道、自身源/目标节点的内部、以及别的边已占的端口锚点**（这是"边永不穿节点"的第一道保证）。**通道刻度**：左族在所有节点左沿之外；右族起点=本边涉及列中更靠右列的**最右沿**+`right_channel_offset`（局部基准——全图基准会把低列内部的长跳推到最右列之外；用列中心在偏移小时会落进节点里，见 D-91），只向外展开，撞更右列节点由逐候选检查拦下。同目标多条回路按**内圈优先**错开入场 `dye`（近源拿靠源一侧的槽位、远源向对侧让位，外圈包内圈嵌套，D-28），避免水平尾段重合。标签沿折线弧长取位：优先中点，压到节点则向两侧滑动，白底徽章遮线 |
| 5 | 碰撞检测与处理 | `validate.py` 八项检查；不过则只调 `<流程名>-flow.yaml` 几何字段后重跑 |

**AI 只在第 5 阶段介入**，且只能改几何，不得改语义。新写的几何值必须落在网格上（见第 0 节）。

## 4. 碰撞检测细则（管线第 5 阶段）

`validate.py` 检查八项，任一项不过返回 1：

1. **引用完整性** — 边的端点、端口、列号、节点类型均有效
2. **节点互不重叠** — 任意两个节点包围盒不相交
3. **边不穿节点** — 折线不穿过无关节点的包围盒
4. **边的端点必须落在源/目标节点的边框上（按真实形状判），且不横穿该节点内部** — 端点查的是"线有没有真的接上节点"：偏移量（`sdye`/`dye`）算错、端口写错、尺寸变化都会让线悬在框外，视觉上节点像没接线。**判据按形状**：矩形类（含胶囊）查四条边，菱形查内接曲线（它只有边中点与矩形重合，只比外接矩形会放行"线悬在斜边外 16~27px"）。横穿部分：端口在边界向外出线不算；从边界横穿进节点内部算——**防的是**端口朝向与走向矛盾时，水平段被节点盖住、箭头落进节点内部，视觉上只剩一条线
5. **边不重叠（正交交叉允许）** — 禁止**没有共同端点**的两条边共线重叠：无关的两条线叠成一条就无从分辨。**允许**正交交叉（一横一竖交于一点，画面是十字而非重合）；**允许**有共同端点且**同向**的边共享出/入段（那是分叉与合流，本就该汇成一点）；**禁止**共同端点上**共线反向**的掉头折返——出边首段把入边末段原路画回，线会压过节点边沿上的箭头（D-15）。合流**只准发生在端口上**：两条**异源**入边共用同一端口时，布线阶段必须按 D-28「近源先拿靠源一侧的槽位」错开 `dye`（见 D-89），并线段长达上百像素时读者看到的是"一条线"，分不出是两个来源
6. **标签压线且不压节点、不压别的标签** — 标签徽章中心落在所属折线上、不覆盖任何节点，且**与其他标签徽章不重叠**（两个词叠在一起，各自都"摆对了"，读者却分不清谁是谁）。
   *只查这三条*：徽章有 `labelBackgroundColor=#ffffff` 白底，**别的线穿过徽章会被白底盖住**，视觉上没问题——所以不做"标签压到别的边"的检查，做了必然把"汇合边共享通道末段"这类正常情况误报成缺陷。
7. **画布内** — 所有节点与折点都在 `canvas.width` / 高度范围内
8. **网格对齐** — 矩形类节点四边落粗格(20)、非矩形格位与全部折点/通道/标签盒落细格(10)、画布尺寸落格

> 通道分配阶段已主动避让节点与自身端点（第 3、4 项的第一道保证）；网格吸附在 `geometry.py` 统一执行。`validate` 是事后复检，兜住绕过几何层的代码路径（第 8 项尤其如此：正常路径不可能触发，它防的是回归）。

处理手段只有三类，按序尝试：调 `row`/`col` 错开节点 → 调 `gutter_*` / `col_gap_step` / `right_channel_*` 挪通道 → 调 `shrink_gap` / `full_gap` 改行距。**不得通过改语义（名称、类型、连线目标）来消除碰撞。** 调几何时数值必须落格，否则会被吸附、与 yaml 不一致。

### 4.1 产物侧复核：只认产物里的真实坐标（**契约**）

上面八项读 `<流程名>-flow.yaml` 并**现算**折线——与渲染器共用同一个 router。router 若把线接歪，两边一起错、
一起"通过"（同错同对）。所以渲染后再做一次**只认产物数字**的复核：

```bash
python flowchart-skill/scripts/validate.py --artifact "output/<名称>/<名称>-flow.drawio"
python flowchart-skill/scripts/validate.py --artifact "output/<名称>/<名称>-flow.html" --dump geom.json
```

**查什么**（清单在 `validate.ARTIFACT_RULES`，与本节逐条对齐）：

| # | 判据 | 依据 |
|---|---|---|
| 1–6 | 节点不重叠 / 边不穿节点 / **端点接在真实形状的边框上** / 边不重叠 / 画布内 / 网格对齐 | 与模型侧同名同义，判据共用一份实现 |
| 7 | **每一段不短于一格粗格（20px）** | 更短是"微残段"，转角挤在箭头上（箭头 10×10，见 D-89），像没画完（D-40）。两种布局都查 |
| 8 | **不得落进左侧里程碑带** | 带宽从产物读（底色带一律从 `x=0` 起画），不靠配置反推——渲染器少画/多画一条带也躲不过（D-39） |
| 9 | **底色必须盖住所有节点** | 底色外包盒也从产物读；底色平移一个走廊宽、或末列没铺到画布右沿，都躲不过（D-41） |

**8/9 两条的"该不该有底图"由底稿拍板，不由产物自称**（第 4–5 步，见 `ARCHITECTURE.md` 9.10）：

- **流程布局的产物**与**泳道源但底图没画的产物**在几何表上**完全同形**（`band=0` / `lanes=None`，
  `examples/workflow` 就是流程布局）。只看产物分不开这两件事，所以这两条判据一度写成
  "缺输入就跳过"——代价是**"泳道源被渲染成流程样"永远绿**。现在改成：
  `build.py` 从 `<流程名>-flow.yaml` 取 `L.lanes() is not None` 作为期望值传下去；
  单独跑 `--artifact` 时拿不到底稿，退化为**按产物自称**（`band` 或 `lanes` 任一存在即视为泳道产物，
  全强度查）——**这是明说的弱化**：单跑抓得到"画了一半"，抓不到"两边全缺"。
- 两个方向都会报错：**该有却没有**（底图没画）／**不该有却画了**（渲染器把布局判错了）。

**不查什么**（别指望它兜住这些）：

- **标签压线 / 压节点**——标签盒不在产物几何里，这一项只在模型侧查（第 6 项）。
- **两份产物是否一致**——读回来的是各自写下的坐标。在 drawio 里手拖过，读到的就是拖后的样子，
  这正是要的（复核成品）；副作用是两份产物各调各的不会被判错。
- **节点可接端点**是**约定的四边中点**（矩形、胶囊、菱形的四个边中点重合），给的是"该接在哪"的参照；
  真正校验的是"线端落在**真实形状**的边框上"（菱形按内接曲线算，胶囊按矩形算）。

**怎么消费**：

- 表里的节点 = 中心 / 尺寸 / 形状 / 四个可接端点；边 = 起点 / 终点 / **产物里写下的端口比例**
  `exit` / `entry` / 全部折点。起点终点就是端口比例按节点矩形反算的——两者摆一起才看得出"为什么接歪"。
- `--dump` 把这张表写成 JSON（泳道另带里程碑带宽与底色盒）；排查"这条线到底连到哪"比读 XML 快。
- `build.py` 末环**遍历渲染器注册表**，对每一份产物各跑一次，**不过则 exit 1，并把刚写下的产物还原**
  ——**渲染契约也一起还原**：它里面的《流程表》指纹是 `sync` 判"表被直改过"的唯一依据，留着新指纹
  等于把那道门禁永久关掉（D-81）
  （审不过的版本不留在盘上）。单独复核任意一份产物用上面的 `--artifact`。

## 5. 视觉自检（质量门禁之外的第二双眼睛）

`validate.py` 只能保证"不重叠/不穿线/不压节点"——**交叉多不多、好不好看，它管不了**。渲染后必须截图看一眼：

```bash
python flowchart-skill/scripts/shot.py "output/<名称>/<名称>-flow.html"                # 全图
python flowchart-skill/scripts/shot.py "output/<名称>/<名称>-flow.html" --crop 0:1200  # 局部
python flowchart-skill/scripts/shot.py "output/<名称>/<名称>-flow.html" --crop 0:1200 --scale 2   # 放大
```

按序核对：

| 症状 | 先查什么 | 再动什么 |
|---|---|---|
| 交叉过多（交叉本身合法） | 并行分支是否该拆到相邻列 | `<流程名>-flow.yaml` 的 `col`（拆列），新列中心 = 上一列 + `col_pitch`（460） |
| **两条线叠成一条**（非法） | 是否有无关的边共用同一通道 | `<流程名>-flow.yaml` 的 `channel` / `gutter` |
| 标签文字与底框错位 | 渲染器 `text-anchor:middle` 是否生效 | `scripts/render_html.py` 的 `.lab` 样式 |
| 标签压线/压节点 | 标签长度（>6 字触发软提示） | 缩短标签，详情挪进「节点描述」 |
| 分支走向反直觉 | 是否该把并行分支放到相邻列 | `<流程名>-flow.yaml` 的 `col` |
| 网格视觉不对齐 | 门禁输出是否有 `· 网格吸附:` 提示 | 把该提示里的离格值改成格上值 |

> 截图脚本走本机 Edge/Chrome 无头模式，不联网。Windows 路径见 `scripts/shot.py` 的 `CANDIDATES`。
