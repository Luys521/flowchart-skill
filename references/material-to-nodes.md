# 从材料到节点（入口 A）

**一句话**：这份文档管**「材料里哪一句话值一个节点」**，`references/flowtable-spec.md` 管**「那个节点在表里怎么写」**。
两者是**前后两问**——这里判"该不该有"，那里判"写得对不对"。**"该不该有"机器拦不了**（H1—H9 只核自洽），
所以本文件是这条链上唯一没有仪器的工位，它的替代品只有两样：**判据**与 **`⚠` 留痕**。

> 定位：**这是尺子，不是模板。** 节点集合由 AI 从材料里读出来（脚本不替你做这件事，也不打算做）；
> 本文件写"读完之后凭什么说这个判断站得住"，所以它给**判据与反例**，不给填空表。
> **先把材料读懂一遍再切句**——边读边落表，切出来的一定是"按段落分块"，不是"按动作分步"。

## 1 读懂一遍，再切句

顺序不可换：**整份读懂 → 说得出它在讲什么事 → 才知道哪些部分是"过程"**。
跳过第一遍的典型后果：把背景、定义、参数也切成了节点，图上于是多出一串**谁也不做的动作**。

切句只问一句：**这句话里有没有"一个动作 +（它产生的）一个东西"**。

| 句子 | 判据 | 落点 |
|---|---|---|
| **步骤** | 有动作者、有动作，做完产生下游要用的东西或状态 | 一个节点 |
| **注解** | 说明边界 / 口径 / 时限 / 责任人 / 例外 / 后果 | **并入相邻节点的「节点描述」或「依据」** |
| **同一步的另一种说法** | 同一动作者、同一动作、同一产出，只是措辞或材料不同 | **合成一个节点**，两处出处都写进「依据」 |

三条最容易看错的：

- **时限、金额、比例、份数**不是动作，是动作的**参数**（→ 描述）；
- **"应当 / 不得 / 视为 / 以…为准"** 多半是规则（→ 描述或依据）；
  **"由 X 在 N 日内完成 Y"** 是**动作 + 参数**：`Y` 成节点，`X` 进「执行者」，`N` 进描述；
- **异述与两个节点怎么分**：看**产出**。措辞不同、产出相同 → 异述（合）；动作相同但**对象或时点不同**
  （对不同对象做的同一动作、分阶段做的同一动作）→ 两个节点（拆）。
  判不准时**选拆**：多一个节点看得出来，少一个节点看不出来。

## 2 一个节点成立的五个条件

> 缺哪条就按"不成立时"处理。**机器只核得动第 4 条**（引用 / 死胡同 / 连通，H3 / H6 / H8）；
> 第 2、5 条它只核"填了没有"（非空），**填得对不对**与第 1、3 条一样——全靠这条尺子。

| # | 条件 | 问法 | 不成立时 |
|---|---|---|---|
| 1 | **有动作** | 能用动词说出来吗 | 是注解 → 并入相邻节点；与别的节点同一动作 → 合并 |
| 2 | **有主体** | 谁对结果负责 | 材料没写就按惯例补并标 `⚠`；连惯例都推不出 → `⚠?` 问用户。**不许留白** |
| 3 | **有产出或状态改变** | 做完之后，下游拿到什么 | 答不上来 → 并入前一个节点（它多半只是前一步的一半） |
| 4 | **有位置** | 至少一条入边或出边（起止各一条） | 悬空的：找到它的前后、或删掉——**不许留在表里当注释** |
| 5 | **有出处** | 能指到哪份材料的哪一处 | 指不到就标 `⚠`（口头需求 / 推断），并在描述里写清"凭什么" |

**第 3 条是分水岭**：判断一句话是不是步骤，最快的问法是"它的产出是什么、谁用"。
答"没有产出"或"没人用"的，几乎都不是节点。

## 3 不该单独成节点的七类

| 类别 | 为什么 | 落点 |
|---|---|---|
| 背景 / 目的 / 意义段落 | 没有动作 | 不影响走向 → 不进表；影响走向 → 进「依据」 |
| 定义 / 术语条款 | 没有动作 | 不进表 |
| 表格里的参数（规格 / 单价 / 比例 / 容量） | 是**别的动作的**输入 | 进那个动作的「输入」或描述 |
| 计价 / 结算口径与公式 | 是规则 | 进相关动作的描述或依据 |
| 罚则 / 违约后果 | **有时含真动作**，见下 | 判据仍是 §2 五条 |
| 目录 / 页眉页脚 / 水印 / 页码 | 不是内容（也不该当证据） | 不进表 |
| 表态 / 承诺 / 会议共识 | 没有产出物 | 若它改变了某一步的前置条件 → 进该步的「依据」 |

**罚则为什么只算"半类"**：它常常**顺带**含一个真动作（发函、催告、扣款、整改）。
判据不是"这句话像不像罚则"，而是 §2 五条——**有动作有产出就成节点，只是"后果"那一半进描述**。

**但"有产出"这一条会在这里失效，得补一条更硬的判据**（2026-09-18 盲读实测补）：
义务、罚则、保密、不可抗力、争议解决这些条款**全都"有动作有产出"**——发函、赔偿、出证明都是动作，
函件、赔偿、证明都是产出。只按"有没有产出"判，它们**条条合规**，于是一份合作框架协议能长出
五六个"节点"，而它们根本不是这条流程里的**过程**。
**分得开它们的唯一判据是 §2 的第 4 条：有没有位置。**

> 问一句"**它的上一步是什么、下一步是什么**"：
> - 真步骤**答得出**（"现场看完了才做方案"）；
> - 义务 / 罚则 / 保密 / 不可抗力 / 争议**答不出**——"什么时候履行保密义务？"答案是**"一直"**，
>   它没有前驱，也没有后继，**它在时间轴上没有位置**，它是**所有步骤共同的前提**。
>
> 判别式一句话：**"发生在流程的哪一步之前 / 之后"——答不上来的，进「依据」或描述，不进表。**
> 这条比"有没有产出"软，但它**可操作**：答不出位置的，一定是规则；答得出的，才是过程。

## 4 判断 / 并行 / 子流程 / 回边：**材料里怎么看出来**

> **怎么写**是 `references/flowtable-spec.md` §2《类型登记表》的事（形状铁律、出口标签、`⊞` 记号）。
> 这里只回答上一问：**材料里的哪句话，让你敢选这一种**。

| 该用 | 材料里的信号 | 用错的样子（反例） |
|---|---|---|
| **判断** | 写明了分路，且**每条路的结果不同**（通过 / 不通过、甲乙两种来源、先到者为准） | ① 所有出口最后汇到同一个节点 → 那多半是**并行**；② 只有一条正常出路，却把"异常"也写成一条边 → 缺一个**结局节点**收住 |
| **并行出口** | "同时 / 并行 / 互不为前置 / 与…同步" | 把"两件事都要做"写成判断 → 图上出现"选一条走"的**假语义**（最容易犯的一类） |
| **子流程（`⊞`）** | 这个节点**自己还讲得出一张图**（≥3 步 + 自己的分支） | 把"两个连续动作"当下钻 → 造一层空壳；把整份材料塞进一个 `⊞` → 主图成了目录 |
| **回边（`→回 X`）** | "重新 / 整改后再验 / 退回上一步 / 未达标则继续" | 回边接到"发起"那一步而不是"重做"那一步 → 图上多出一段**没人走的环路** |

**并行与判断只差一个字：走一条，还是都走。**材料没明说时按**串行**落表并标 `⚠`——
把串行写成并行会凭空造出两条同时进行的路，比漏一个分路更贵。

**"并行"要落地，得先找到那个岔口**：本表的并行只有一种表达——**同一个节点的多条出边**（全都走）。
所以听到"这两件事同时进行"，还要再问一句"**它们从哪一步分出去的**"：

- **找得到共同岔口** → 在那一步上开多条出边（这才是并行）；
- **找不到共同岔口**（两份材料各说一条线，谁也不提从哪分开）→ **落成串行并标 `⚠`**，
  在描述里写明"现实中与 X 并行"，**不许为画出并行而造一个不存在的岔口节点**——那是拿结构凑语义，
  比串行更坏（它会让读者以为图上那个岔口是材料里有的）。

> 这一条是**盲读实测补的**（2026-09-18）：一个只看材料、没看过已有表的读者，把四份各自成链的材料串成了一条主链，
> 并在报告里主动写"现实中运营结算与尽调/交割是并行的，**本表表达不了**"——"表达不了"的真因是**没有共同岔口**，
> 不是表不支持并行。写清这一条，下一个读者才不会把"我找不到岔口"误记成"这个工具画不了并行"。

## 5 粒度：拆还是合

- **合**：同一主体、同一时点、**同一个产出**的多句话 → 一个节点；
- **拆**：**产出不同**，或中间**有人要点头**（签字 / 确认 / 回复 / 批复）→ 拆。
  "多一个人点头"必须拆——它的产出是**"同意"**，而"同意"是下游的前置条件；
- **一句话判据**：**同一产出合成一个，多一个产出就拆一个。**节点名称里带着斜杠或"与"、
  而产出其实有两个（例："复勘与报价""设计并编制清单"）→ 回 §2 第 3 条重新数一遍产出；
- 表长到几十个节点、开始出现"这一段其实自成一体"时，先想 `⊞`（§4），再想加节点。

## 6 「依据」怎么指（可追溯的落点）

1. **指到最小可引用单元**（证据账本里的 `id`），不是"某份材料"、不是页码——
   页码是人的读法，`id` 是机器的读法（两处引用同一件事时，只有 `id` 能机器比对）；
2. **一个节点可以有多处出处**：同一动作在两份材料里都说到，**两处都写**——它既是溯源，也是"两份材料互相印证"的记号；
3. **逐字引用与"我看到的"分档**：视觉来源（扫描件 / 照片 / 截图 / 白板）一律按**推断档**标 `⚠`——
   它是读数，不是原文；把它写成逐字引用，等于给账本里塞一条无法复核的引用；
4. **依据还能用来裁决冲突**：两份材料对同一件事说法不同时，把"以哪份为准"的那条依据**写进这一行的「依据」**，
   并在描述里写清谁让谁——**别只在脑子里裁**，图上没人看得见。

（"这一步为什么存在"与"凭什么这样做"是两个问题，分别由 `⚠` 与「依据」回答——
两个都空等于你没想过，细则见 `references/flowtable-spec.md` §2。）

## 7 落完表回头数两遍（自检）

| 方向 | 问什么 | 发现不对时 |
|---|---|---|
| **正向（怕漏）** | 材料里的每个"步骤句"，在表里有没有下落？ | 补一个节点，或明确写进某节点的描述——**不许默默丢掉** |
| **反向（怕编）** | 表里每个节点，回材料里能不能找出那句话？ | 找不出 → 标 `⚠`（有依据的推断）或删 |
| **同类项** | 两份材料 / 两处说的是不是同一件事？ | 合成一个节点、两处出处都写；**两条同义节点会让图上出现两条平行路** |
| **结局** | 每个"没通过 / 终止 / 放弃"的分支，有没有一个节点收住？ | 补一个结局节点（形状校验拦死胡同，但"失败也是一种结果"是**语义**，只有你能讲清） |

**两遍都要跑**：只跑正向会漏掉"编出来的节点"，只跑反向会漏掉"材料里明写着却没进表"的步骤。
这一步的产出不是"我觉得差不多了"，而是"**两遍都数过了**"——说不清数过没有，就是没数。

## 8 与校验的分工

```bash
python scripts/table_to_dsl.py --check "output/<名称>/flowtable.md"
```

- **H1—H9 管"自洽"**：编号、类型与出边、引用、连通、回路、表头键。它拦得住**写错的表**，
  拦不住**理解错的表**（把并行写成判断、把注解写成节点、把两步并成一步——它全绿）；
- **本文件管"合理"**：该不该有、是不是同一步、判断还是并行、粒度拆合、依据可不可指。
  它**没有仪器**，靠判据 + `⚠` 留痕 + 人的一眼；
- 所以这条链上唯一负责的姿势是：**拿不准就标 `⚠`，不要用"看起来合理"的话术抹平**。
  图上那个醒目虚线框（`⚠` 节点）就是这条纪律的产物——它把"我没把握"显示在用户唯一会看的那张图上。
