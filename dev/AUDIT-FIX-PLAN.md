## 3 风险隔离（第 3 步：先隔离，再按计划设计）

1. **护栏先行**：批 0 先上（不动样例）。它让批 1 的错自己红——这是最划算的一层隔离。
2. **回滚点**：动批 1 之前打 `git tag audit-base`。批 1 一次性做对；做不对就整体退回，**不修补丁**。
3. **锁死的四条断言，每批必跑**：`contract.py`（模板逐字一致 · 引用路径存在 · 参数存在）· 门②（H1–H9）·
   门④/⑤（几何）· 门⑨（审美）。样例一动，这四条同时受压——**这正是"同批"的理由**。
4. **一次性脚本的边界**：只许落 `.accept_tmp/` 或 `%TEMP%`，**不许落 `output/`**（`output/` 曾经有 10 个我的一次性脚本
   混在成果根里，见 §4）。
5. **删除动作**：先列清单（§4）、只删我自己的、**不是我的一律先问**、删前确认未被 git 跟踪（跟踪区里没有可删的）。
6. **材料只读**：清场**不动任何材料**（`output/` 里那几份 pptx / wps / md 是用户放进来测的，见 §4）。

**落盘规范化（三条，写进 `SKILL.md` 与 `AGENTS` 级约定）**：

1. `output/` 只放**任务成果根**与**本仓自己的构建产物**（`self-boot/`）；**一次性脚本与草稿一律不进 `output/`**。

- **不给 `21/22/23` 各开一张 `⊞`**：`20` 已经展开循环内部；再拆是把一条回路切成四张图。
