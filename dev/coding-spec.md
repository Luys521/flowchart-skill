# coding-spec.md — 代码质量自检对照表

> 用途：回答"**这条行业原则在本仓库由什么拦**"。
> **本文不重复任何规则的内容**：每条规则的家在「本仓库的规则（唯一出处）」那一列指向的文件里，这里只做
> **索引 + 覆盖状态**（同一条纪律见 `SKILL.md`「一条规则只陈述一次」）。审代码时逐行问两件事：
> **规则还在不在？拦它的仪器还在不在？**
> 与 `dev/ARCHITECTURE.md`（模块怎么切）／`dev/REPO-MAP.md`（数据怎么流）分工：本文管"**写得对不对**"。
> 行业出处：PEP 20《Zen of Python》· Google Eng-Practices《代码评审标准》《看什么》·
> NASA/JPL《The Power of Ten》· MISRA C / AUTOSAR C++14 / SEI CERT C（机检规则族）· ISO/IEC 25010（可维护性）。

## 一、状态记号

| 记号 | 含义 |
|---|---|
| **机** | 有仪器拦：改了会红。右侧点名**仪器 + 段名**，可照名字去 `verify` 输出里找那一行 |
| **记** | 纸面有、仪器不拦，靠改的人记着。**这就是缺口**，全数列在第三节 |
| **不适用** | 面向 C／安全关键或特定范式的条目，在本工具链上没有对应物——写明为什么，不许拿"已遵守"糊过去 |

仪器名字的四种前缀：**面①～面④** = `dev/verify/run.py` 的四个面；**门①～门⑩** = `dev/tools/accept.py`
的十道门；**仪** = `dev/tools/` 下单独跑的仪器；**手** = 人工/子代理通读。

## 四、怎么用这张表

- **审代码**：从上往下逐行问"规则在不在、仪器在不在"。发现"规则在、仪器没了"＝**回归**，比新缺陷更该先修。
- **加规则**：先给它找一个仪器；找不到就登记到第三节——**不许假装它被守住了**。
- **减规则**：先删仪器再删规则，否则留下的是一条没人守的纸面条文。
- **判新原则**：行业原则进本表要么落成"机"（有仪器），要么落进第三节（承认靠人记）；两者都不选，就别写进规范。

> **这一节的作用是"下个会话别重新提议"**：每条都给出证据位置与一句"为什么不值"。级别只分两档：
> 不值得做（收益 < 成本）· 不该做（与既有纪律冲突）。

| # | 不做的事 | 为什么不值 / 不该做（证据） |
|---|---|---|
| N1 | 不做"基线重钉"脚本 | 顺序错的**后果**已被"自举树基线含 28 张表 + 重造逐字节相同"兜住（`examples/README.md`「刷新基线」） |
| N2 | 不给注释设体积指标 | `contract.py` 的 `注释归属` 段明写：体积不是冗余，机械裁判会逼人"删掉有用注释去凑数" |
| N3 | 不把 `esc`/`_esc`/泳道底图/边标签发射抽进公共层 | 模块层零横向 import 是门⑦底线；三份共享的只有约 6 行算术，markup 天生不同（`render_drawio.py` `esc` 上方、`render_svg.py` 文件头各写过一次理由） |
| N4 | 不引入新形状 / 类型白名单 | 四类型 ←→ 三形状是 D-74 铁律；`RECT_SHAPES` 那次是**收窄**，不是扩形状 |
| N5 | 不改 `Report.all_same` 的返回语义（D-85③） | 它同时被 `--json` 与尾行消费；逐条补条目更小 |
| N6 | 不把 `DEFAULT_COL_X` 搬进字典 | 它是**内部展开基准**（用户调的是 `col_pitch`）；家在 `geometry` 已只有一个真值（D-84⑥） |
| N7 | 文本宽度启发式不换 `unicodedata.east_asian_width` / 不引 `wcwidth` | 实测 30 个真实标签下两者**逐字同值（0 处不同）**；`0x2460–24FF` 那段是**有意的政策声明**，换标准库后 A/F/W 的取舍还得另写一条（`semantics.py:208-211`） |
| N8 | 不把五处"占位符集合"收敛成一个常量 | 五处回答的不是同一个问题（字段空值 / 解析终止符 / 图例占位 / 改动归一），合并会造出**假的单一真源**；且"等价占位符不算改动"已有机检（`gates.py` 伪 diff 那节） |
| N9 | 不把 `TYPE_RULES` 阈值搬进 `dictionary.yaml` | 字典自称"可按图覆盖的**视觉映射**"，而 H1/H4 是结构门禁——进了字典就成了 per-diagram 旋钮；松紧的唯一档位是 D-55 的 `--quality` |
| N10 | 不改 `Finding(str)` 为 dataclass / 不强制包装 | D-55 的零改动迁移选择：`gates.py` 有 331 处 `c.check`、69 处直接点名 H 编号文案，改类型=重写整个输出面 |
| N11 | 不抽 `('rhombus','ellipse')` 为常量 | 形状集是**键封闭**契约（N4），"漏改"的输入在纪律上不存在；`RECT_SHAPES` 是正向登记、这是补集，立常量等于把补集写成第二处真值 |
| N12 | 不把布线 `tries`/`sweeps` 提进字典 | 它们是**算法搜界护栏**（防死循环 / 迭代上限），不是要被人按图调的画布参数；一旦可调，视觉退化会从"过不了门禁"扩到"过得了门禁但难看" |
| N13 | 不统一 `fit_base_height` 的取整口径 | 分叉只在用户填**离格值**时发生（本就违规）；改成 `snap` 只是把 100 换成 80——换一种同样任意的答案，还要重钉自举树 |
| N14 | 不把形状反查扩到 drawio/svg | 已有几何自检按产物自称形状兜住大半；剩下能抓的只有"几何恰好等价、形状仍旧错"那一种，为它造两层对称守卫=给已有机检的规则再加一层 |
| N15 | 不把注册表的 `ids`/`geom` 合并成一个 reader | 两者对应**两个消费者**（契约反查 / 几何门禁），合并正好违反"第二个消费者就不许合并"；writeback 只走 `read()`，不要几何 |
| N16 | 不把 `xml_reader` 的兜底列坐标收回唯一出处 | 兜底只在"外部图一个 `mxGeometry` 都没有"时走到（drawio 存盘必写）；要改得给 `assign_grid` 穿 cfg 参数=接口变更，收益为零 |
| N17 | 不合并 `manifest.check` 的 `html=`/`drawio=` 与 `products=` 两条分支 | 前者是文档承诺的公开 CLI，后者是 W6 给编排层的通用入口；合并=把注册表形状泄漏进契约模块 |
| N18 | 不把渲染器常量（`MAX_VIEWS`/`SUB_INSET`/`EDGE_FLOW_*`）提成字典或 CLI | 它们是**规格**不是参数：2px/1px/55% 是 D-78 实测定的，`MAX_VIEWS` 是护栏且撞上限已显式报出 |
| N19 | 不把 `render_html` 的 CSS/JS/整页模板外置成文件 | 产物必须自包含（D-52），源侧外置一个字节都不减，只多一条"资源读不到"的失败路径；而那段字符串里的注释正是 D-76/78/79/80 的取舍记录 |
| N20 | 不让 `render()` 返回 receipt 字典 | 统一契约在 ARCHITECTURE 9.8 已改判成"成功信号 = 显式 `return 0`"；回执字段 build 末尾已算过并打印（D-55④） |
| N21 | 不让 `build.STAGES` 驱动执行 | 它存的是**函数对象**，与"注册表只存名字、调用时现查 globals()"正相反——那正是 `gates` 靠替换模块名证明替身被调到的前提（会让替身用例假绿） |
| N22 | 不把 `_render_ctx` 的分派搬进注册表描述符 | ctx 是**调用期数据**；装进模块级常量就得放函数对象，撞 N21 同一条纪律，而 W2→W3、W5→W6 已两度为"改注册表结构"返工 |
| N23 | 不把 14 处 `stdout.reconfigure` 抽成公共 helper | 这条规则**已有仪器**且判据是字面量（`contract.py`「入口命令都要重设 stdout 编码」）；抽走字面量断言当场红——为已机检的规则再加一层 |
| N24 | 不做"一次 `engine.load` 全链复用" | 阶段之间的接口**就是路径**，这是 9.1 定的契约形状，且 `gates`/`invariants` 正是当 CLI 直接跑渲染器 |
| N25 | 不给 `coverage --allow` 找常驻白名单消费者 | 它按设计是"一次性排查的逃生舱"；接进门③等于让验收自己给自己发豁免，"100% 覆盖"当场失去意义 |
| N26 | 不把 `accept` 的截图探针与 `shot.py` 的命令行抽成同一处 | 探针只有一个消费者，且它刻意独立于 `shot.py`（要比的正是"这台机器按这条命令能不能落图"）；动 `shot.py` 公开面还要走 API 记账 |
| N27 | 不把 `coverage`/`selfboot_gen`/`hygiene` 的正则与字面量集合抽公共层 | 三个消费者的语义不同（摘名字 / 保证生成器造的名字落在外侧 / 动态出口花名册），抽出来只是一个正则常量；且两份不同步会被各自的告警撞出来 |
| N28 | 不给"见某文档某节"加锚点机检 | 锚点形态无法机械解析（章节/表/函数名混用），必然要白名单；空锚点读者一搜即知，不像静默丢数据那样瞒得住 |
| N29 | 不加"生成器新鲜度"门 / 不给门⑦ 补"表比图旧"的 mtime 判据 | 后果已由面③"按图重造自举树并逐字节比"守住；不重跑生成器的廉价检查只能重述顺序，属**假仪器**（`accept.py` 自述"不重跑生成器"） |
| N30 | 不给 `accept` 加 `--only`/`--skip` | 与它"一条命令跑完、只给一个结论"的存在理由冲突：过滤器会开出"跳过已知红的那道门、照样退 0"的口子 |
| N31 | 不把 `hygiene` 的判据扩到 `dev/` | `dev/` 的 4 处未用 import／死函数不改变任何产物字节与退出码；而把 `dev/` 塞进依赖图会让 `coverage` 的分母多出上百个 dev 函数 |
| N6 | 不把 `DEFAULT_COL_X` 搬进字典 | 它是**内部展开基准**（用户调的是 `col_pitch`）；家在 `geometry` 已经只有一个真值 |
