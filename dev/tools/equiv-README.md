# `dev/tools/equiv.py` —— 重构的「可观测行为等价」比对仪

一句话：**同一件事，在「工作树现状」与「隔离底本」上各跑一遍，逐字节比结果。**
命令行用法与纪律写在 `dev/tools/equiv.py` 的文件 docstring 里（`python dev/tools/equiv.py --help`）；
本文件补上两样 docstring 放不下的东西：**覆盖本机公开命令面的用例清单**、以及**这套工具盖不住的等价性维度**。

## 它解决什么问题

函数级原子化拆分（把一个函数体内一串阶段拆成多个私有函数）唯一的安全性依据是「行为逐字节不变」。
这类改动**看不出来对不对——只能比**。没有统一工具时每个拆包的人各写一份临时脚本，口径各不相同：
有人 `strip()` 了输出、有人忘了比退出码、有人拿整目录回退把队友的并发改动也一起回退了。
于是「我这边是绿的」变成一句无法复核的话，而且**假差异比没差异更坏**：你会去修一个不存在的问题。

本工具把口径固定成四件事，任何人在任何时间跑都是同一套判据：

1. **原始字节**：不 strip、不替换路径、不忽略空白、不统一换行。唯一的排序是 `tree` 按相对路径枚举（只为报告可读）。
2. **三件套**：`stdout` / `stderr` / 退出码，三者全同才算「相同」。
3. **显式列出回退了哪些文件**：差异只可能来自这几个人这几个文件。
4. **差异必须能定位**：给出两侧字节数 + **第一处差异字节的偏移** + 前后各 80 字节上下文。

退出码：全相同 `0` ／ 有任何不同 `1` ／ 仪器故障 `2`（底本不存在、命令起不来）。
`1` 与 `2` 分开，是为了让「命令根本没跑起来」不被误读成「行为变了」。

## 60 秒上手

```bash
# ① 造隔离底本：只把「我改的」文件回退到重构前那个提交，其余保持工作树现状
python dev/tools/equiv.py make-base --rev api-base --dest /tmp/base \
    --file scripts/flowtable.py --file scripts/flowtable_check.py

# ② 比 CLI 行为（{side}=代码根、{work}=数据区，两侧逐侧替换）
python dev/tools/equiv.py cli --base /tmp/base --scratch /tmp/eq --cwd '{side}' -- \
    '{py}' '{side}/scripts/table_to_dsl.py' --check '{root}/dev/tools/equiv-fixtures/broken.md'

# ③ 比文件产物 / ④ 比目录整树
python dev/tools/equiv.py files --base /tmp/base --scratch /tmp/eq '{work}/out/tour/tour-flow.yaml'
python dev/tools/equiv.py tree  --base /tmp/base --scratch /tmp/eq '{work}/out/tour'

# ⑤ 按清单批量跑（58 条比对 + 1 条预备，覆盖下面那张表）
python dev/tools/equiv.py suite --base /tmp/base --scratch /tmp/eq --cases dev/tools/equiv-cases.json
```

**两个根，别混用**：`{side}` 是**代码**根（工作树 / 底本目录，用来指 `scripts/<模块>.py`）；
`{work}` 是**数据**根（`--scratch` 下的一个目录，**两侧共用同一份，每次开跑前清空**）。
产出的东西一律放 `{work}`，工作树那一侧也不往仓库里写。

> **为什么必须共用数据区**：初版给两侧各一份数据区，结果 `--write` / `build` / `render_*` / `sync`
> 几乎全部报「不同」——不是行为变了，而是这些命令会把**产物绝对路径回显到 stdout**，两个目录的路径
> 字符串本来就不一样。要修就得归一化输出（把路径替换掉），而那正是本方法论**禁止**的事。
> 所以改成**同一份数据区，先跑完工作树侧、清空、再跑底本侧**。代价是两侧不能并行，对本用途完全可接受。

## 用例清单（`dev/tools/equiv-cases.json`，共 58 条比对 + 1 条预备）

`copy` / `prep` 是「只做不比」的预备步骤（在 `setup` 或 `cases` 里都行）：**照样会真的执行**，只是不计入相同/不同。

### 有意不进清单的两个命令

- **`shot <html> [-o] [--crop] [--scale]`** —— 要本机装 Edge/Chrome，产物是 PNG（二进制，且受字体/渲染/时序影响）。
  它作为「仪器」不够稳，进了清单会把「本轮机器状态变了」冒充成「代码行为变了」。
  需要时单独跑：两次截图同机同浏览器、比 sha256；不一致就说明它不能用于本方法论。
- **`dev/tools/fn_graph.py`** —— 它是给人看的静态分析产物，且重生成会与他人抢占 `dev/tools/fn-graph.json`。
  拆分期间不要跑（团队约定：全部拆包结束后统一重生成）。

## 自测（证明这台"仪器"不是永远报"相同"）

拿同一份坏表跑同一条命令，只让底本差一处：

- **必然相同**：底本 = 只回退了 4 个被拆分的文件（`c71cb46`），行为不变 →
  `相同  cli  … table_to_dsl.py --check …broken.md` ／ `退出码: 1 vs 1` ／ `stdout 相同（2529 字节）` ／ `退出码 0`
- **必然不同（CLI）**：底本再把 H2 报错文案改一个字（`编号重复` → `编号重覆`）→
  `不同` ／ `stdout 2529B vs 2529B` ／ `首处差异 @802（±80 字节上下文）`，上下文里 `\xe9\x87\x8d\xe5\xa4\x8d`（重复）
  与 `\xe9\x87\x8d\xe8\xa6\x86`（重覆）并排可辨 ／ `退出码 1`
- **必然不同（产物）**：底本把 `templates/flowtable-template.md` 末尾加一行注释 →
  `不同  init 产物整树` ／ `统计 {work}/out/demo: 文件数 2 vs 2；共有 2，内容不同 1` ／
  `flowtable.md … 7683B vs 7729B` ／ `首处差异 @7683`，上下文里能读到那行 `<!-- equiv-mutant: … -->` ／ `退出码 1`

## 这套工具**盖不住**的等价性维度（适用边界，诚实列出）

1. **只验跑过的路径**。没被用例触发的分支（异常分支、平台分支、环境变量分支、`--force` 之外的组合）
   等于没验。**用例的覆盖面就是结论的覆盖面**——想扩大结论只能加用例，不能靠"我觉得不会走到那"。
2. **它不能证明重构正确，只能反驳"重构改了行为"**。它不判断「这两段代码逻辑等价」（那是静态审查），
   也不判断「底本本身是对的」。缺了用例的形态（更深的嵌套、特殊标点、超大表、CRLF/LF 混用、带 BOM、
   非 UTF-8 输入）就是没验。静态工具（`fn_graph` 等）是**另一层**，不能互相替代。
3. **非确定量会冒充差异**。产物里若含时间戳、UUID、临时目录名、`set`/`dict` 迭代顺序（跨进程哈希随机化）、
   并行完成顺序，两侧天然不同 → 假差异。本工具**刻意不归一化**，正是为了不掩盖真差异；代价是这类量
   必须自己先消除，或用 `--env PYTHONHASHSEED=0`（两侧同注，不掩盖差异）固定住。
   本清单里的用例都是确定性路径，所以两侧能逐字节一致——这是**被验证过的事实，不是假设**。
4. **性能与资源完全不在内**。只比字节，不比耗时/内存/句柄/磁盘。慢十倍、吃十个 G 都算「相同」。
   报告里的 `sec` 只是参考值，**不参与判定**。
5. **并发与时序**。两侧串行跑，不比并行行为、锁、竞态、中断恢复。
6. **交互与终端**。只比管道下的 `stdout`/`stderr`；TTY 宽度、颜色、分页、交互输入、Ctrl-C 不覆盖。
7. **进程外的世界**。浏览器（`shot`）、字体、外部转换器渲染出来的结果不可靠；
   写仓库文件、调网络、改环境变量/注册表这类**不可逆副作用**工具只管、也只看 `{work}` 与 `{root}`
   下能观察到的文件——它不会阻止你造成副作用，也回不去。
8. **进程外的信号**。被 kill、超时（当仪器故障报，不当行为差异）、OOM/ulimit 不在判据里。
9. **单条 `files` / `tree` 的先决条件**：`{work}` 每次开跑前清空，所以单条 `files`/`tree` 只能比
   `{side}` 下的**代码/资源文件**。要比产物，必须走 `suite`（用 `setup`/`prep` 或前置命令先生成）。
10. **一条比对只能比「两侧同名路径」**，不能断言「内容等于某份参考文件」。
    所以「被拦后原表一字节未动」这类断言，工具只给两侧一致的快照 sha，**要人去和上一条快照对照**
    （清单里就是这么摆的：`换表后原表快照` → `被拦后原表快照`，两条 sha 应当相同）。
11. **底本的时效性**。底本是**造的那一刻**的副本；`make-base` 之后队友再改别的文件，两侧就会因为
    队友的改动而产生差异（不是你的）。所以：**跑比对前重新 `make-base`**，且底本目录别跨轮复用。
