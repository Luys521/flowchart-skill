# `dev/tools/` —— 七件仪器的地图（清单的唯一出处；另有一件清场工具 `sweep.py`，不算仪器）

这里放**开发期的仪器**（不参与产品运行时；`dev/verify/contract.py` 已把 `dev/tools/` 排除出产品文档扫描）。
七件仪器各答一个问题，**谁都不替代谁**。先看下面这张表，再翻到对应小节。

## 我该跑哪个？

| 我的问题 | 跑哪件 | 一句话 |
|---|---|---|
| 函数之间谁调谁？一组一组的边界在哪？ | `fn_graph.py` | 产出函数级依赖图（**事实源**），另几件拿它当输入之一 |
| 每个函数都画进图了吗？ | `coverage.py` | 图的成员 vs `flowtable.md` 里的节点名（`--tables-root` 指向流程表树），裁决"画全了没有" |
| 原有的函数名 / 签名 / 嵌套关系丢了吗？ | `api_audit.py` | 拿一个 git 底本（`--rev`；或 `--base-dir` / `--base`）比**函数面**：丢失 / 改名 / 签名变更 / 新增 |
| 我这次的改动改变可观测行为了吗？ | `equiv.py` | 工作树 vs 隔离底本各跑一遍，**逐字节**比 stdout / stderr / 退出码 |
| 谁依赖谁、方向对不对？ | `layering.py` | 分层门禁：模块层只许依赖公共层，越层即退 1 |
| **有什么是白写的？** | `hygiene.py` | 没人引用的 import + 没人调的模块级函数（只看当前工作树，不要底本） |
| **图读起来顺不顺？** | `aesthetic.py` | 三条审美律的读数：主轴偏心 / 绕行率 / 通道半径（`visual-spec` §0.1，D-91） |
| **自举树怎么来的？** | `selfboot_gen.py` | 把函数级依赖图落成**流程表树**（`output/self-boot/`）——收口仪式的第 2 步，跑完还要 `build.py` 再与基线比（见下节） |
| **改了 scripts/ 之后怎么收口？** | `repin.py` | 重钉基线：生成器 → build → 两棵基线（**不 commit / 不 tag / 不跑验收**，那三件要人过目） |
| **工作区怎么这么大？** | `sweep.py` | 清场：删掉本仓库自己生成的临时物（验收 / 自检现场 + `__pycache__`），**绝不碰 `output/` 与基线** |
| **同一个东西写了几遍？** | `cohesion.py` | 内聚/耦合读数：跨模块重复函数体 · 接口面宽度 · 单消费方公共函数 · **允许边上的环**（**只报不判红**） |
| **十一道门一次跑完？** | `accept.py` | 验收器（见文末"验收：一条命令"）；它自己不是门，是**跑门的那台机器** |

一句话记住：**`fn_graph` 是事实源；`coverage` / `api_audit` / `hygiene` 是静态的（看代码、看图），`equiv` 是动态的（真跑命令、比字节）。**
`coverage` 问「**画全了吗**」，`api_audit` 问「**丢没丢**」，`hygiene` 问「**白没白写**」——三件互补，不替代。

## 七件仪器

### `fn_graph.py` —— 事实源：函数之间谁调谁

- **职责**：对 `scripts/*.py` 做 AST 静态分析，产出函数级依赖图与三份衍生视图。判不出的分记两本账：
  `unresolved`（可能有缺口）与 `ambiguity`（候选明确、运行期才定）——**不猜**。
- **典型命令**：`python dev/tools/fn_graph.py`（**无参数**）
- **产物**：`dev/tools/fn-graph.json`（主事实源）、`dev/tools/fn-groups.json`、`dev/tools/fn-deps.json`、`dev/tools/fn-graph.md`
- **退出码**：**没有退出码契约**（`__main__` 直接调 `main()`；成功即 0，异常直接抛栈）。
  它不参与裁决，只供另几件消费。
- **关键边界**：只读 `scripts/`，**绝不修改它**；`segments`（顶层顺序段数）只是"函数体是平铺多段流水"
  的**可计算提示**，**不代表语义上真能拆**；**产物是快照**——代码改了必须重跑，否则 `coverage.py`
  就是在拿旧图裁决新代码。

### `coverage.py` —— 画全了没有

- **职责**：把函数依赖图的成员，和 `flowtable.md` 里的节点名对账，四类差异分开报：
  缺失 / 多余 / 重复 / 错位。
- **典型命令**（下面两条**都实跑过**，退出码见括注）：
  ```
  python dev/tools/coverage.py --tables-root dev/tools/coverage-fixtures/ok/tree \
      --graph dev/tools/coverage-fixtures/ok/graph.json --allow dev/tools/coverage-fixtures/ok/allow.txt   # → 0
  python dev/tools/coverage.py --tables-root dev/tools/coverage-fixtures/gaps/tree \
      --graph dev/tools/coverage-fixtures/gaps/graph.json                                             # → 1
  ```
  真实收口时：`--tables-root` 换成要裁决的流程表目录树，`--graph` 可省（默认 `dev/tools/fn-graph.json`）。
  要给循环裁决消费就加 `--json`。
- **`--tables-root` 该指哪棵树**：**就是 `output/self-boot/`**。真实的产出结构是**两层**——
  `output/self-boot/flowtable.md`（根表：每模块一行 + 「项目运作阶段」列）、
  `output/self-boot/<模块名>/flowtable.md`（每模块一张，**节点 = 该模块的函数**）。
  （曾规划过"再插一层阶段表"的三层方案，已撤销：分组信息用根表的阶段列承载即可，见 `ARCHITECTURE.md` 第七节。）
  映射规则是「**目录名即模块名**」，所以这条规则在**任意深度**都成立、递归逻辑不用为层数特判；
  根表的目录名（`self-boot`）不是模块名，走「表映射不到任何图文件」提示（非失败）。
  `examples/workflow/` 之所以不适合当模块树，是因为它的 `parts/` 下放的是**阶段名**
  （`渲染` / `结构校验` / `同步回写`），本来就不是模块树。
- **退出码**：**0** = 100% 覆盖且无多余、无重复、无错位；**1** = 有缺口；**2** = 输入读不了
  （图缺失 / 目录不存在 / 解析失败）。
- **关键边界**：分母只收图里 `kind ∈ {function, method}` 的项（**类不算**，只作参考数字单列）；
  **节点名不像 Python 标识符的按"结构性节点"整个摘出去**，所以真·函数名若写成中文或含空格
  会被一起吞掉 → 覆盖率虚高；为此它带一条**防静默告警**（`graph_name_warnings`，不影响退出码，
  但一定印在 stdout 上）。
- **`--tables-root` vs 别家的 `--root`**：本工具的树根指**流程表目录树**，和 `equiv.py` /
  `api_audit.py` 的 `--root`（**代码工作树根**）不是一回事——同名不同义，是最容易踩的坑。
  为兼容既有命令与文档，`--root` 仍**当隐藏别名**收着（可用、但 `--help` 里不露面），新命令一律写
  `--tables-root`；漏掉这个选项时按 argparse 惯例报用法错并退 **2**。

### `api_audit.py` —— 函数面丢没丢

- **职责**：同一个文件，从**某个 git 版本**与**工作树**各取 AST，比**函数面**
  （`qualname` / 参数名序列 / 每个参数的默认值存在性 / `*args`·`**kwargs` 名 / `kind`），
  分四类：丢失 / 改名 / 签名变更 / 新增。
- **典型命令**：
  ```
  python dev/tools/api_audit.py --rev api-base                                # 全仓
  python dev/tools/api_audit.py --rev api-base --file scripts/flowtable.py    # 只审自己那一包
  python dev/tools/api_audit.py --rev api-base --json                         # 给 CI 消费
  python dev/tools/api_audit.py --base-dir /tmp/base                         # 底本改用一棵目录树
  ```
- **底本从哪来**：`--rev`（git 版本，默认 `api-base`——本仓的底本 tag，重钉用 `git tag -f api-base <rev>`）与 `--base-dir`（一棵目录树）**二选一**。
  `--base` 是 `--base-dir` 的**别名**——与 `dev/tools/equiv.py` 的 `--base` 同义（都是"底本目录"），
  两个名字收的是同一件事、任意给一个即可；`--help` 里只列主名，别名不露面。
- **退出码**：**0** = 无「丢失」且无「签名变更」；**1** = 有（这两类才是"严重"）；
  **2** = 输入读不了（git 版本不存在 / 目录找不到）。
- **关键边界**：**函数被拆成两个、名字都变了 → 判不出**（函数体指纹不同，落进「丢失 + 新增」）；
  「改名」分**精确档**（函数体归一化后逐字符相同）与**近似档**（函数体比值 ≥ `--near`，默认 0.75，
  报告里印出比值）——近似档是**启发式**，必须人复核。改名**不计入失败**（它是这类重构的预期产物），
  `--near 1.0` 可切到最严档。

### `equiv.py` —— 行为变没变

- **职责**：同一件事，在「工作树现状」与「隔离底本」上各跑一遍，比 `stdout` / `stderr` / 退出码，
  **原始字节**（不 strip、不替换路径、不忽略空白、不统一换行）。
- **典型命令**（`/tmp` 换成你的临时目录）：
  ```
  python dev/tools/equiv.py make-base --rev api-base --dest /tmp/base --file scripts/<我改的>.py
  python dev/tools/equiv.py suite --base /tmp/base --scratch /tmp/eq --cases dev/tools/equiv-cases.json
  python dev/tools/equiv.py cli --base /tmp/base --scratch /tmp/eq -- '{py}' '{side}/scripts/<脚本>' --check '{work}/t.md'
  ```
  另有 `files`（比文件产物）与 `tree`（比目录整树）两个子命令；`--base` 是 `make-base` 造出的底本目录。
- **退出码**：**0** = 全相同；**1** = 有任一不同；**2** = 仪器故障（底本不存在 / 命令起不来）。
  **1 与 2 分开**，是为了让"没跑起来"不被误读成"行为变了"。
- **关键边界**：**只验跑过的路径**——没被用例触发的分支等于没验，**用例覆盖面 = 结论覆盖面**；
  两侧共用一份数据区并刻意**不归一化**，所以时间戳 / 随机顺序这类非确定量会冒充真差异；
  它**只回答"跑出来的字节一不一样"**，不做代码级等价推断。
- **怎么按清单跑**：就一行 —— `--cases dev/tools/equiv-cases.json`。清单条目本身、每条比 CLI 还是产物、
  以及**这套工具盖不住的 11 个维度**，见 `dev/tools/equiv-README.md`（这里不重复）。

### `layering.py` —— 分层门禁：谁许依赖谁

- **职责**：按「**公共层 / 模块层 / 编排层**」的归属，检查依赖**方向**。三条规则（详见文件头）：
  ① 模块只单向依赖公共层，**模块层之间不许有代码依赖**（它们的协作走产物，那是数据流不是 import）；
  ② 公共层可以互相引用，但**不许反向依赖上层**；③ 编排层（`build` / `sync` / `parse`）是流水线驱动者，允许依赖上面两层。
- **典型命令**：`python dev/tools/layering.py`（无参数，读 `dev/tools/fn-graph.json`）
- **退出码**：**0** = 无违规；**1** = 有违规（逐条列出「谁 → 谁 + 被引用的函数名」）；**2** = 输入读不了（图缺失 / 有新模块没归层）。
- **为什么值得单设一件**：`manifest → render_html` 这种"公共层回头拿模块层一个常量"，在源码里只是**函数体内的一行延迟 import**——读代码看不见、跑测试不报错；把全部模块的 import 按层摊开比对，方向错了才现形。
- **反向控制夹具**：`dev/tools/layering-fixtures/ok.json`（→ 0）与 `bad.json`（→ 1，里面就是修复前那条违规边）。
- **与另几件的区别**：那几件是**度量**（回答"变了没有 / 画全没有 / 白写没有"），这一件是**约束**（回答"方向对不对"）。
  实测记录：上线前 **1 条违规**，修好后 **0 条**（25 模块 / 69 条依赖边：`module→public` 25 · `orch→*` 18 · `public→public` 26）。

### `hygiene.py` —— 白写检查：没人用的 import / 没人调的函数

- **职责**：只看**当前工作树**，报两类：① import 了但整文件既没读到那个名字、也没把它当字符串提过的绑定；
  ② 没有任何调用者、且不属于"静态图必有假缺口"那几类的**模块级函数**。
- **典型命令**：`python dev/tools/hygiene.py`（可加 `--json`；读 `dev/tools/fn-graph.json`）
- **退出码**：**0** = 干净；**1** = 有发现；**2** = 输入读不了（图缺失 / 不是合法 JSON）。
- **判据为什么只到"模块级函数"**：静态调用图在本仓结构上有三类**必然漏报**，实测会让 510 个函数里
  误报 40 个——`__init__`（图中指向它的调用边为 **0 条**）、`engine.load` 门面（`L.width`/`L.grid.Y`
  动态挂上，解不出接收者）、**按名查表**（`build._RENDERER_SPECS` 用字符串指定 `'ids': 'read_svg'`，
  再 `globals()[name]` 取；这是**故意的**，为了让 `gates.py` 能替换 `build.render_html` 而不假绿）。
  所以方法/类一律不判，上述三类整类排除——**宁可漏报，不可误报**。
- **与另几件的区别**：`coverage` 问"画全了吗"、`api_audit` 问"丢没丢"、本件问"**白没白写**"。
  它不需要 git 底本（只看现状），也不判"设计是否合理"。

## 生成器与顺手工具（不算仪器）

### `cohesion.py` —— 内聚 / 耦合读数：**同一个东西写了几遍**（只报不判红）

**为什么它不算仪器**：它没有"过 / 不过"——三张清单里没有一条是"错"，全都**要人裁**。
（所以也不进 `accept.py`：把"供人裁的清单"塞进会红的门里，只会逼人给它加白名单。）

```text
python dev/tools/cohesion.py             # 三张表
python dev/tools/cohesion.py --dups      # 跨模块近似重复函数体
python dev/tools/cohesion.py --width     # 接口面宽度：谁 import 谁、一次带几个名字
python dev/tools/cohesion.py --single    # 只被一个模块 import 的公共层函数（G5 那张清单）
python dev/tools/cohesion.py --single --limit 0   # 全打（默认只打 20 行；逐个裁决要看全部，D-125）
python dev/tools/cohesion.py --cycles    # 允许边上的环（公共层互引 / 编排层互引；D-127）
```

**`--cycles` 是 2026-09-19 补的**（D-127）：`REPO-MAP` 与 D-123 都写着"公共层无环"，而那**是一句人工结论**——
`layering.py` 只打印边数与方向违规、**不查环**（`selfboot_gen._find_cycle` 查的是**流程图**的环）。
D-123 那条甚至把它归因成"`layering` 现算"。现在这句话有了随时可现算的读数，**并且面③ 还钉住
"仪器报得出非零"**（喂一张造出来的 `a↔b`）——不然"环：无"可能只是个恒真的装饰。

**`--limit` 是 2026-09-19 补的**（D-125）：那张清单有 46 行，而它原先只打前 20 行——
**仪器打印不出它要审的那张清单**，裁决得改代码才看得见全部。三张表各有一个 `--limit`（0 = 不截断）。
裁决结果留档在 `dev/COHESION-AUDIT.md`（46 条逐条判据 + `esc` / 边标签的终审）：**46 / 46 保留**，
所以下次要问"这条该不该抽"时，**先翻那份留档**，不必从零再判一遍。

**四台"方向类"仪器管不到的正是它**：`layering` 管方向、`hygiene` 管白写、`coverage` 管画全没有、
`equiv` 管行为变没变——**没有一件管"同一段逻辑在两处各写一遍"**。
2026-09-19 人工审计量出四处该收口，量完脚本就删了；这件工具是那个脚本的常驻版。
**它第一次跑就多抓到两处人工漏掉的**：`load_thresholds` 的第 6 份（`recon`）与
`_import_dep` 三份（`parse_pdf` / `parse_ooxml` / `recon`）——这就是"临时脚本 vs 常驻仪器"的差别。

**它的已知盲区要说清**：`--dups` 的语句数下限是 5，所以**只有 1 条语句的逐字重复它看不见**
（`esc` 三份同体就是这样漏的）；而"公共层函数"的分母只认 `from X import …`，
**被注册表按名字现查的反解器**在它眼里和"没人用的函数"长得一样（`hygiene` 同样看不见）。
前者由产物级的 `_check_escape`（面②）兜住，后者写在 `dev/COHESION-AUDIT.md` §1。

**判据为什么要两条**（缺一条会漏一整类）：**结构相似**（语句种类 + 字面量 + 名字，去文档串）
抓"逻辑一样、措辞不同"；**逐字行占比**抓"连注释都抄过去"的。短函数里文档串常占一半篇幅，
把它算进结构相似会虚高、去掉又虚低 ⇒ **两个数都报，谁高算谁**。

**`selfboot_gen.py`** —— 把 `fn-graph.json` 落成**流程表树**：根表一行一个模块、每行 `⊞` 指向该模块
的函数表（`output/self-boot/`）。它是**收口仪式**的第 2 步，顺序不可换：

```text
python dev/tools/fn_graph.py        # ① 事实源（改了 scripts/ 就要重跑）
python dev/tools/selfboot_gen.py    # ② 落成流程表树
python scripts/build.py output/self-boot/flowtable.md   # ③ 出三份产物
# ④ 与 `dev/baseline/self-boot/` 逐字节比（面③ 会自动做这件事）
```

**`repin.py`** —— 上面那串（外加两棵基线的同步）收成一条命令，**顺序写在它里面**：

```text
python dev/tools/repin.py --dry-run   # 造出来但不动基线：只报"会动哪些文件"
python dev/tools/repin.py             # 真重钉；--prune 连"基线里多出来的"也删
```

**它不替你** commit / `git tag -f api-base HEAD` / 跑验收——那三件要人过目（"这一版产物我认了"是判断，
而 tag 是"等价门"的底本，自动打等于把门变成橡皮图章）。跑完它打印下一步。
**为什么值得有**（`coding-spec` N1 原先写着"不做"）：N1 兜的是顺序错的**后果**，不是**过程**——
手工那六步在这一版会话里跑了八次、漏过一次；`repin.py` 还把旧写法里那个 `find dev/baseline -name
flowtable.md -delete`（**全仓递归**，曾删掉整棵自举树的表）换成**按树作用域**的删除（D-117、G2）。

### `sweep.py` —— 清场：把"自己生成的临时物"删掉

**为什么不算仪器**：它不裁决任何东西（没有"过 / 不过"），它只**腾地方**。之所以还要写下来，
是因为**攒的速度比人记得清的速度快**：`accept.py` 的现场每跑一次 5.7 MB / 140 个文件，
连跑十几轮就是 **134 MB / 2579 个文件**（实测，D-113）。

```text
python dev/tools/sweep.py --dry-run    # 只报：哪些、多大、合计
python dev/tools/sweep.py              # 真删；删不掉的逐项报出来（退 2，不假装成功）
```

**只认三样**：`.accept_tmp/`（验收现场）· `.verify_tmp/`（自检现场）· `__pycache__/`（字节码缓存）。
**绝不碰**（代码里写死的白名单）：`output/`（**用户的**流程产物与材料）· `dev/baseline/`（比对基准）·
`examples/` `references/` `templates/`（一手内容）· `.git/`。它连"扫全仓找大文件"都不做——
清场工具最容易出的错就是**顺手多删了一层**。实测它还救回一处：`.accept_tmp/blind/arm2/资料包/` 里
留着一份**用户材料包的拷贝**（含 9.6 MB 的 PDF），只读属性让 `rmtree` 删不动 ⇒ 现在会先去只读再删。

## 七件仪器的关系

- **`fn_graph` 是事实源**：`coverage` 与 `hygiene` 直接吃它的 `fn-graph.json`；`api_audit` 与 `equiv` 不吃它，
  但六件盯的都是同一批 `scripts/*.py`。
- **静态 vs 动态**：`fn_graph` / `coverage` / `api_audit` / `hygiene` 只读源码与产物，**不改变任何东西**；
  `equiv` 会**真的跑产品命令**，所以它的结论建立在"这些命令确实被跑到了"之上。
- **`coverage` 与 `api_audit` 互补（这条最容易搞混）**：`coverage` 的分母来自**图**、图来自**当前代码**，
  所以它只裁"代码 ↔ 图"是否一致——**代码和表一起改掉时，它没有任何信号**。
  "函数面有没有丢"必须由 `api_audit` 独立回答：它的分母钉在一个 **git 底本**上，不随工作树漂移。
  反过来，`api_audit` 不看图，所以"函数都还在、但没画进表"只有 `coverage` 能发现。
- **`equiv` 与前三件互补**：静态工具说"东西还在、也画了"，只有 `equiv` 才回答"跑起来还是原来那样吗"。
- 补一句口径：`coverage` 虽属静态阵营，却会 **import 产品自身的表解析器**来读表
  （"验证要验的就是那份解析器，另写一个等于验了个假的"），所以它比另两件静态工具更贴着产品。

## 验收：一条命令

收口时不必人肉按顺序跑五条命令再自己汇总：`dev/tools/accept.py` 把收口清单固化成一台仪器。
它调子进程时统一带上 `PYTHONUNBUFFERED=1` 与 `PYTHONDONTWRITEBYTECODE=1`——前者保证卡住/被杀时
抓到的输出不丢尾部，后者保证**跑完验收不在仓库里留 `__pycache__`**（那是运行产物，不是仓库内容）。

```text
python dev/tools/accept.py                     # → 0 = 十一道门全过
python dev/tools/accept.py --tables-root output/self-boot   # 换一棵表树（默认就是它）
python dev/tools/accept.py --allow-soft        # 门②不因软提示报红（默认 hard 与 soft 都要求 0）
python dev/tools/accept.py --keep              # 门全过也留着现场（默认成功即收本次新建的）
```

**十一道门**（判据**全部从被跑命令的输出里读**，不写死任何计数——写死会在下次改动后变成假绿）：

| 门 | 覆盖 | 谁决定它过不过 |
|---|---|---|
| ① 套件 | `dev/verify/run.py` 四面：contract / gates / invariants / e2e | 每面 `【面…】N/M 通过` 行 + 套件退出码 |
| ② 结构 | 表树每张 `flowtable.md` 过 H1–H8 + 表头 H9（H10 要账本；自举树没有 ⇒ 它由门⑪ 的材料链夹具覆盖） | `table_to_dsl.py --check --json` 的 `hard` / `soft` 条数 |
| ③ 覆盖 | 每个函数都画进表了吗 | `coverage.py --tables-root` 的覆盖率行与 `✓/✗` 结论行 |
| ④ 几何 | 每张**模块表**的几何单独过 `validate` | `validate.py <模块>-flow.yaml` 的退出码 |
| ⑤ 出图 | 根表能不能 build 成三份产物（html / drawio / svg） | `build.py` 退出码 + `⚠` 告警**分类计数**（13 族；每行 `⚠` 必须**恰好**归一族，否则仪器故障） |
| ⑥ 回执 | 这份结论对应哪一版树 | 全树 `flowtable.md` 的表文本摘要 + 整树摘要 |
| ⑦ 分层 | 依赖方向对不对 | `layering.py` 的退出码 + 违规清单；**跑之前先查依赖图是不是旧快照**（任何 `scripts/*.py` 比 `dev/tools/fn-graph.json` 新 → 直接判**仪器故障**，因为图旧时门③ 与门⑦ 会一起假绿） |
| ⑧ 卫生 | `scripts/*.py` 的"白写"归零（未用 import / 没人调的模块级函数） | `hygiene.py` 的退出码（0 过 / 1 有白写 / 其它=仪器故障）。**射程只有 `scripts/`**：`dev/` 的未用 import 不改变任何产物字节，为它把 `dev/` 塞进依赖图会让门③ 分母多出上百个 dev 函数（D-88 / N31） |
| ⑨ 审美 | 三条审美律的读数不许退化：主轴偏心 / 绕行率 / 通道半径（`references/visual-spec.md` §0.1） | `aesthetic.py` 的读数与退出码；阈值以 `references/visual-spec.md` §0.1 为准（当前收口值见 `dev/coding-spec.md` G12） |
| ⑩ 等价 | 夹具自身有效 + 工作树可观测行为与底本 tag 逐字节相同 | `table_to_dsl --check` 对 `dev/tools/equiv-fixtures/*.md` 的期望结果；`equiv.py make-base` / `suite` 的退出码（0 全同 / 1 有不同 / 2 仪器故障） |
| ⑪ 材料链 · 漂移 · 取子集 | `PIPELINE-SPEC` §5 的循环发动机：漂移判据 D1—D5 + `check` 的**账目对账**（说谎 / 过期 / 无理由都要被抓住）；§5.3 的点名取子集（分批 + 游标 / 范围 / 关键词 / 语法错退 2）；pptx 全链（判 T1 / 出摘要 / 按张撬开 + 超限留痕）；§3 清点卡片（`intake.py` 正反例）；legacy 逐族提示；§1.5 侦查（`recon.py` 正反例）；**规范列模板逐字等于仪器列规范** | `pipeline-fixtures/suite.py` 的 `PASS/FAIL` 行与退出码（0 全符 / 1 有不符 / 2 夹具自身造不出来）。夹具在系统临时目录里**现造现跑现清**，不往树里写字节 |

**退出码**（与七件仪器同一套约定）：**0** = 十一道门全过；**1** = 有门未过；**2** = **仪器故障**
（表树不存在 / 命令起不来 / 输出解析不了）。**1 与 2 分开**，是为了让"命令没跑起来"不被误读成"门没过"。

**两条口径**：
- **门⑤在仓库外的副本上跑**：`build.py` 会往树里写 html / drawio / `.bak`，而验收**不该改产物**，
  所以整棵树先复制到临时目录再 build（副本根目录仍叫 `self-boot`，产物名与实际交付**逐字一致**）。
  临时目录一律落在仓库外，且**每次唯一**（`mkdtemp`）——**不许"先删再建"**：那会撞批量删除的安全
  钩子，把"门全过"变成"命令报错"，两者不是等价改写。
- **退出码只由各道门决定**：结论印完之后**退出码就不再变**，清理动作一律在结论之后、且 `ignore_errors`
  （删不掉只多印一行）。**成功时收掉"本次新建的"那几项**（2026-09-19 改，D-113；进门之前先记现场里
  已有什么，只删增量）；**没过 / 仪器故障一律留着现场**；`--keep` 留着，`--scratch` 是你给的目录 ⇒ 不动。
  原先写的是"只占约 2 MB、不替你删"——实测**每跑一次留 5.7 MB / 140 个文件**，连跑十几轮攒到
  **134 MB / 2579 个文件**，而没人会想起来清；存量用 **`python dev/tools/sweep.py`** 收。
  同理，被调子进程一律带 `PYTHONUNBUFFERED=1`：否则卡住/被杀时抓到的输出会少掉尾部，
  判出来的不是"门没过"而是"账对不上"这种假仪器故障。
- **门⑤的告警账本是 13 族**（`accept.py` 的 `BUILD_WARNINGS`）。它**穷举**了"会打进 build stdout 的
  `⚠` 行"——注意范围不只是 `build.py` 自己：`build.py` 在**进程内**调 `table_to_dsl.main` 做结构校验
  与转 DSL，后者的 `⚠ 软提示（不阻断…）` 也落在同一条 stdout 里，所以也在账内：
  `未内嵌·结构校验未过` / `未内嵌·转 DSL 失败` / `未内嵌·DSL 读不动` / `已内嵌但几何未过` /
  `新增节点·复用旧几何` / `嵌套超过 5 层` / `内嵌视图超过上限` / `未内嵌·DSL 读不动·子孙未枚举` /
  `未内嵌·子表不存在` / `层级索引·告警族` / `AI 推断留痕` / `软提示·不阻断` / `布局提示不存在`。
  **过不过**：`rc == 0` **且**一行 `⚠` 都没有才算过（有告警 = 未过，与"仪器故障"是两回事）。
  告警本身不一定代表错（软提示就是正常的），但**收口态的自举树应为零告警**——判"未过"是为了让人
  先看清它属于哪一族、是否预期，而不是说"有告警 = 坏了"。
  **总数按"`⚠` 开头的行"数**，不按 `⚠` 字符数——`⚠ 软提示（…打 ⚠ 留痕）：` 这类行行内还有第二个
  `⚠`，按字符数会把一条告警数成两条、凭空造出"账对不上"。**任何一行归不了族（漏了一族）或归了两族
  （表该拆细）都当场报仪器故障**，并列出那些行的原文，提示去同步这张表。
  **`⚠` 行以外的告警不在账内**：`✗` 硬错误、`· 层级索引: …` 这类正常行、以及 `契约: …⚠ 推断 N`
  （该行以"契约:"开头）都不参与计数。
  **这些族大多潜伏**：self-boot 的子表数 = 模块数 + 1（**现跑现取，别在这里手抄**）、无坏表、
  无软提示 ⇒ 只触发其中极少数，实际 0 条；
  其余要**造夹具**才会现身，例如 **超过 `render_html.MAX_VIEWS`（64）个视图**触发 `内嵌视图超过上限`
  （截断，连被截表的子孙一起计入）、**坏子表 DSL** 触发 `未内嵌·DSL 读不动·子孙未枚举`（读不动 ⇒
  它的子孙既枚举不出来、也不在内嵌/校验之列）、表树里留一张没人用 `⊞` 引用的 `.md` 触发
  `层级索引·告警族`。**改了 `build.py` 的打印就得重跑穷举**：
  `grep -rn "⚠" scripts/*.py | grep print`——凡是会进 build stdout 的，都要在 `BUILD_WARNINGS`
  里有且**只有**一族。
- **门⑥是回执型门**：摘要没有阈值，它"不过"只意味着树为空或读不了；把它列成一道门，是为了收口时
  **必须报出**"这组数字对应哪一版树"，否则数字和树对不上账。它印**两个口径**，
  **对比回执时按目的挑**：
  - **表文本（内容口径）** = 只算 `flowtable.md`，与产物、与 build 历史都无关 → **比"表改没改"用它**；
  - **整树（产物口径，不含点开头文件）** = 排除 `build.py` 留的 `.self-boot-flow.*.bak` 备份
    → 去掉构建历史后**应可复现**（同一棵树跑两次 build 摘要不变）→ **比"交付物变没变"用它**。
  **为什么另一条会变**：`.self-boot-flow.html.bak` 这类文件是**上一次渲染的副本**，
  每 build 一次就轮换一次；把它算进"整树"，同一棵树的回执就会随构建历史漂移、跨轮不可比。
  点开头文件在本仓一律是备份 / 元信息（`.gitignore` 同一口径），所以整树口径**整体排除**它们，
  不做逐名白名单。

**它盖不住什么**：只验自举树 + 套件 + build，**不验产品 CLI 的其余命令面**；**不重跑生成器**
（那会重写产物），所以"生成器仍确定性"要在验收之外单独比两次摘要；门①的结论**覆盖面 = 套件用例的
覆盖面**；门④验的是盘上**已展开的几何**，不验"提示→几何"那一步。

## 跑之前要准备什么

1. **`equiv.py` 跑之前必须先 `make-base`，而且"底本有时效"**：底本是**造的那一刻**的副本；
   `make-base` 之后别人再改文件，那一侧的差异就**不是你的**了。
   → **每轮比对前重新 `make-base`，底本目录别跨轮复用。**
2. **`fn_graph.py` 的产物是快照**：代码改了要重跑，否则 `coverage.py` 拿旧图裁决新代码。
   （协作约定：**拆分/改造期间不要跑 `fn_graph.py`**，它会把 `fn-graph.json` 等四份产物一起重写、
   和别人的重生成互相覆盖；要重生成请在收口时统一做。）
3. **`coverage.py` 依赖图**：图不存在时它直接退 2，并提示先用 `fn_graph.py` 生成。
4. **不往仓库里写数据**：`equiv.py` 的产物全落在 `--scratch`（默认系统临时目录）；
   `coverage.py` / `api_audit.py` **不落任何产物文件**（前者会 import 产品的表解析器，
   可能留下 `__pycache__` 字节码缓存，那不是产物）。
5. **换机器 / 换目录 / 刚克隆下来时，表树与图快照都不在**：`output/self-boot/`（表树）与
   `dev/tools/fn-*.json`（图快照）都是**派生物**，`.gitignore` 把它们排除了 ⇒ `accept.py` 的门②③④⑤⑥
   会一起报"仪器故障"。**那是"还没生成"，不是"门没过"**；先按顺序跑一次生成器再验收：

   ```bash
   python dev/tools/fn_graph.py && python dev/tools/selfboot_gen.py
   python dev/tools/accept.py
   ```

   （顺序不可换：表树由图快照派生。`accept.py` 自己在表树缺失时也会印这条修复指令。）
