> 状态：**设计中、未实现**。本文件是 L0—L4 契约的**唯一出处**；实现与本文不一致时，先改本文再改代码。
> 读者：**改这个仓库的人**。出图时的 AI 不需要读它（维护区，见 `dev/REPO-MAP.md`）。
> 先读：`dev/ARCHITECTURE.md`（模块怎么切）、`dev/REPO-MAP.md`（数据怎么流）。
> 组织：§0 术语 → §1—§4 逐层规范（探测 / 账本 / 清点 / 计划）→
> **§5 循环的发动机（漂移 → 缺口）** → §6—§8 接缝、边界与登记。**写一节、审一节**。
>
> **§5 的位置不是排版偏好**：§1—§4 各管一层，§6 管 L0 与既有结构校验的接缝，
> 但它们串起来**不是一条单向流水线**——真实过程是"先落表（带假设）→ 表暴露漂移 → 漂移定位缺口 →

## 0 术语（只在这里定义一次）

| 术语 | 定义 | 不许混用 |
|---|---|---|
| 材料 | 用户给的原始文件。**只读，永不修改** | 不是"证据"，也不是"流程表" |
| 证据 | 材料解析后的**最小可引用单元**（element） | 不是"材料"本身，也不是流程图上的"节点" |
| 证据账本 | 一次任务的全部证据，落盘为 `evidence.json`（唯一事实源） | 不另存手改的 md 视图—双份必漂 |
| 清点 | 对材料做编目：每份一张卡片 | 不是"校验" |
| 材料卡片 | 一份材料的记录：档位 / 主题 / 是否含流程 / 读不动原因 | |
| 计划 | 流程清单 + 关系 + 映射 + 待澄清，落盘为 `plan.md` | **不是"流程表"**：计划说"做几张、谁依赖谁"，流程表说"这一张怎么做" |
| 流程表 | 唯一事实源，12 列（列规范见 `references/flowtable-spec.md`） | 计划 ⇒ 表 ⇒ 图，三段不许互相代替 |
| 子流程 | 被父流程的**一个节点展开**出来的流程，走 `⊞` + `parts/` | 只有"甲"算嵌套（§4，未写） |
| 出处 | 证据的位置：材料 + 页/表/单元格/坐标 + 摘录 | |
| 推断留痕 | `⚠`：AI **有依据**的推断，不问用户 | 与"待裁决"是两回事 |
| 待裁决 | `⚠?`：AI 推不出、**必须**用户拍板 | |
| 澄清申请 | 面向用户的一组问题（每问附推荐答案） | |
| 澄清答复 | 用户对澄清申请的答复。**它是新材料**：回 01 重走探测→解析→落账，不许就地改表 | 与现有 07→回 01 同一条纪律 |
| 漂移 | **表里的一条断言与"已知道的"不一致**。"已知"只有三源：证据账本 / 假设账 / 表自身；判据 D1—D6 见 §5.2 | 不是"表写得不好看"，也不是**结构错误**（那是 H1—H9 的地盘，§6） |
| 缺口 | 为消掉漂移、补上逻辑环而**必须补上、手头却没有**的东西（落 `drift.md`，§5.3） | **不是"澄清申请"**：澄清申请只是它里面"必须业务方拍板"的那一类 |
| 取证 | 按缺口**定向**撬开材料 → 产物落盘 → 子代理读成摘要（§5.5）这一段动作 | 不是"解析"（解析是 §1.4 适配器的职责）；取证是**有具名消费者、被缺口限定范围**的那一次解析 |

材料标识：`M01`、`M02`… 编号顺序 = **材料路径字典序**（同一次任务内稳定、可复现）。

**责任边界**：本流水线交付的是**可追溯的重建**，不是**正确性担保**（用户只对最终渲染图负责，见 `SKILL.md`）。
因此：填不出的字段、判不出的归属、读不动的材料，**一律留痕**（`⚠` / `⚠?` / 读不动），不许用"看起来合理"的话术抹平。

**任务级产物住哪**：`evidence.json`、`intake.md`、`plan.md` 都住**成果根**（用户给的路径，或 C 档默认根），与各 `<流程名>/` **平级**；**流程目录里只有原七件套**（`flowtable.md`、`checklist.md`、`<流程名>-index.md`、`<流程名>-flow.{yaml,manifest.json,html,drawio,svg}`）。

**自包含优先，环境能力只当加速器**（硬约束）：本 SKILL 必须能**独立跑**—**不许依赖宿主环境里的任何其它技能或工具**。
- 每条能力都要有一条**自包含实现**（只用本仓 `scripts/` + **显式声明的依赖**）。
- 宿主恰好提供的能力**只在探测到时可选用**，用来提速/提质，**不许成为唯一路径**（降级要留痕：见 §1.4 的 `extractor`）。
- **环境要求要显式声明**：哪些格式需要外部工具，缺了给**可执行**的提示，不许静默降级、也不许假装能读。

## 1 格式三档 + 内容探测

### 1.1 三档定义

| 档 | 含义 | 谁读 | 典型格式 |
|---|---|---|---|
| T1 直读 | 抽取器直接给出文本/结构 | 解析器插件（脚本） | `.docx` `.xlsx` `.md` `.txt` `.csv` `.json` 等 |
| T2 转换后可用 | 需转换器抽一次，抽完等价 T1 | 转换器插件（脚本） | legacy `.doc` `.xls`、**文本型** `.pdf`、`.html` |
| T3 需视觉 | 文字与结构都在像素里 | **AI 视觉** | **扫描型** `.pdf`、`.png` `.jpg`、截图、白板照 |
| T4 不参与 | 与流程无关或读不动 | — | 音视频、可执行文件、探测失败者 |

### 1.2 探测规则：**按内容，不按扩展名**

硬理由（实测）：真实材料里两个 `.pdf` 会分属 T2 与 T3；legacy `.doc`/`.xls` 与 `.docx`/`.xlsx` 扩展名像、容器完全不同。

```text
1) 扩展名 → 候选档（只是先验，不作结论）
2) 魔数/容器探测：
   PK..          → OOXML/zip 容器 → **按"确切部件在不在"判**（word/document.xml / xl/workbook.xml /
                   ppt/presentation.xml）；判据与读它的那个适配器**同源**，见下面的不变式
   D0 CF 11 E0   → OLE 复合文档 → T2（legacy doc/xls）
   %PDF          → 查文本层：抽前 N 页，字符密度低于阈值 → T3，否则 T2
   图片魔数      → T3（不用扩展名判，防改名）
   压缩包        → 先列目录，再对每个成员递归判档（不许直接标 T4）
3) 探测必须记账：每份材料一行 {档位, 类型 kind, 依据}；探测失败 → T4 + 原因，不许猜
```

**一条不变式（可机器核）**：**`tier=T1`（可直读）⇒ 必须至少有一个适配器认领。**
探测的**声明不许比读者的射程宽**——"T1"的含义就是"抽取器直接给出文本"（§1.1），
没有读取器的格式（如未落地的 `.pptx`）只能记 T4 + 可执行提示，不许说它可直读。

**为什么把这条写成不变式**（2026-09-18 审计实测，三类硬失败都由它兜住）：
- `probe` 曾按**目录前缀**判 OOXML（`word/` 在就行），而 `parse_ooxml` 要的是**确切部件**
  （`word/document.xml`）⇒ "有 `word/` 却没有 `document.xml`"的包被判 T1 却没人认领；
- `.pptx` 被判 T1 可直读，而本仓**没有 pptx 读取器**（python-pptx 是可选依赖、未落地）；
- 合法 xlsx 改名 `.et`（WPS 后缀）：探测认了，而 `openpyxl` **按扩展名拒收**。
三类都让分派器判"漏认"并**整条链退 1、不落盘**。修法不是在分派器加特例，而是：
**判据与 reader 同源**（同一句部件名）+ **没有 reader 就不许判 T1** + **读者按内容开门**
（`parse_ooxml` 从内存 `BytesIO` 打开，不让扩展名投票）。

**`kind` 是机器可读的材料类型**（封闭枚举，见 §2.1）：本仓"这是什么"的**唯一判据源**是 `probe`。
侦查 / 适配器 / 渲染**只许读 `kind` 与 `tier`，不许按扩展名或魔数重判**——审计实测过：
同字节材料改个文件名（真 docx 改名 `.doc`），两处判据就给出互相矛盾的结论
（一边建议"直读"、一边建议"调 soffice 转换"），而"按内容判"正是本节的第一条理由。

**可解析格式清单是开放式的**：它由插件注册表**派生**，不在本文里手写一份封闭清单—手写清单必漂（见 `dev/coding-spec.md` 第三节 G7）。
上表的「典型格式」只是例子，不是边界。

N 与密度阈值属**数值**：落地时必须写进 `scripts/dictionary.yaml`（数值只有一个家），本文只写"要探测什么"。

### 1.3 三档的产出义务

- T1/T2：产出进证据账本，`extractor` 写具体插件名；**且必须过 §1.5 的抽取质量门**——
  抽不出来算读不动（诚实），抽出来是碎片 / 坏字符则**不许当 `direct` 证据**（污染唯一事实源，且没有仪器看得见）。
- **T3 也必须产出证据**（element 带 bbox 与摘录）—否则流程表「依据」列会指向空，H10 断链。T3 的 `extractor` 记 `vlm`，`certainty` 一律 `inferred`（视觉推断不许伪装成直取）。
  **产出的路**：`render_pages.py` 把材料渲成图（PDF 走 pdfplumber + pypdfium2，**自包含**；图片材料本来就是图，直接读原文件）→ AI 读图 → 填工具给的骨架（`text` / `bbox`）→ `render_pages.py check` 校验 → 交账本。
  **引用它的节点按推断档走**（`⚠` / H10.2）：视觉读数是"我看到的"，不是"文件里逐字写着的"——**不许当逐字引用**。
- T4：作为 materials[] 的一条记录进账本（status=unreadable + reason，见 §2.1），**不静默丢弃**；清点只读账本，不另立一份。
- **"读没读出来"由解析阶段记账**（材料层补注，见 §1.4）：`extractor` 写走的是哪条路，读不动的写 `status=unreadable` + **可执行**原因。
  这一条不是补充说明，是**必要的一环**：`probe` 只能给档位——4 份 legacy 与"能读的 legacy"在探测阶段长得一模一样，
  没有补注，账本上它们就是"tier=T2 / status=ok / 零证据"，看着像能读却没内容。

**这一版 T2 与 T3 都要做**（不是"先用能读的那些起步"）：T2 走转换器（legacy 二进制、文本型 PDF），T3 走视觉解析。两条路产出的文字同样要进账本、带出处—否则 H10 断链。

### 1.4 解析器插件的接口契约（"可插拔"的最小面）

```text
name                                  插件名（写进 element.extractor）
supports(探测结果)        → bool   它认不认这一档/这一种容器
extract(材料路径, options) → {elements[], warnings[], error?}
notes                     → [{material_id, status?, reason?, extractor?}]   材料层补注（见下）
```

**材料层补注（notes）**：材料层由 `probe` 起头（档位 / 魔数依据），"这份到底读出来没有、走的是哪条路"
只有解析阶段知道。补注是唯一把这条现场事实送回账本的路，**只许改 `status` / `reason` / `extractor` 三个字段**
（键封闭），由 `ledger.py --notes` 校验并落盘，**落完再校一次**（`unreadable` 必须有 reason）。
**不归自己管的材料不许补注**：`parse_ooxml` 看到 legacy 只说"不是 OOXML"，**不下"读不动"的结论**——
那是 `parse_legacy` 的地盘，抢着下就是双份真值。

**分派是查表，不是判断**：档位到读者的映射是固定的（T1/T2→脚本、T3→视觉、T4→只记账），没有裁量余地；
流程图上这一步的执行主体是**脚本**，不是 AI。

**分派器 `scripts/parse.py`**（编排层）：按**固定顺序**跑各适配器（`parse_ooxml → parse_pdf → parse_legacy → parse_text`），
合并产物与补注，可一并把账本写掉（一条命令 = `probe → parse → ledger`）。它这张表里**只有顺序，没有判据**——
"什么材料归谁"由各适配器自己认领（认不出的**不记账**，留给别人）。再抄一份格式清单就是**第四份真值**
（`probe` 的档位 + `kind` + 各适配器自己的认领判据已经在说这件事），必漂。

两条硬要求：**元素按 `material_id` 稳定排序**（材料内部保留该适配器的阅读序）——同输入同字节；
**冲突与漏认都退 1 且不落盘**：
- **冲突**：同一 element id 被两个适配器产出（判档重叠），或两份补注对同一材料写出不同的值——静默取一个会
  让账本里出现"没人知道哪来的"记录；
- **漏认**：`probe` 说 `status=ok`，却**既无元素、也无补注**（例：纯文本材料至今没有适配器）——
  这正是账本里最隐蔽的那个洞（"能读却没内容"），不许再让它静默流进账本。
  **它上线当轮就抓到一个真 bug**：`probe` 用 8 字节头判文本，中文一个字 3 字节正好被切断 ⇒
  合法中文 `.txt` 被判 T4；已改成 4 KB + 允许尾部截断（另补 UTF-16 BOM）。

**自包含优先，环境能力只当加速器**（按材料类型分工；**降级必须留痕**）：

| 材料 | **自包含路径（必须实现）** | 可选加速器（**探测到才用**） | 都没有时 |
|---|---|---|---|
| OOXML（docx / xlsx / pptx） | Python 库（python-docx / openpyxl / **python-pptx 未落地**）—**依赖要显式声明**（见下）。**读者按内容开门**：从内存 `BytesIO` 打开，不让扩展名投票 | 宿主本地 Office SDK（若存在） | 记 T4 + **给可执行提示**（装什么）；**没有读取器的格式不许判 T1**（§1.2 的不变式） |
| **文本型 `.pdf`（T2）** | `pdfplumber`（**纯 Python**，无外部二进制）抽文本层—一页一个 element | — | 记 T4 + **可执行提示**（装 pdfplumber） |
| **legacy**（.doc / .xls / .ppt） | **没有纯 Python 的可靠读法** ⇒ 只用**外部转换器**（LibreOffice / soffice，若装了）：转成 OOXML 再交给 T1 适配器抽（§1.1 的 T2 定义就是"转换后可用"），`extractor` 写 `soffice+py:docx` | 宿主本地 Office SDK（若存在） | 记 T4 + 可执行提示（"请另存为 .docx" 或 "装 LibreOffice"） |
| 图片 / 扫描件 / 截图 / 白板照 | `render_pages.py` **转图片**（图片材料本来就是图，直接读原文件） | **宿主多模态模型**（判据：AI 自报本会话能否直接看图）；OCR（tesseract / paddleocr，可选依赖） | 记 T4 + 进澄清 |
| 纯文本（md / txt / csv / json …） | `parse_text.py`（**只用标准库**）：**解码 + 按行打块**（一块一个 element，`extractor=py:text`；标记 / 数据文件写 `py:code`）、`.csv` / `.tsv` → `table` + `rows`。**不认结构**（见下） | **宿主模型直读文本**：理解归它 | 直读不可用时仍走得通（标准库永远在） |

**能直读的格式：理解归模型，记账归脚本**（这一条把"要不要给文本写解析器"定死）：
`.md` / `.txt` / `.csv` / `.json` / `.yaml` / `.xml` / `.html` 宿主模型**能直接读**，而且比任何结构识别读得好
——所以 `parse_text.py` **不认标题、不认列表、不抽表格语义**，它只干记账那件事（可引用 id / 可复现 /
编码与上限）。给它加结构识别 = 与直读重复，而且**认错了会让 `kind` 撒谎**（账本是唯一事实源，撒谎代价最高）。
反过来说：直读**只用于"理解"，不许当证据来源**——要引用就必须引账本里的 element id（§2.5 / H10），
"我记得文件里写着…"是一条无法机器复核的引用，正是 H10 要断的链。

**纯文本的编码不猜**：只认 UTF-8 与**带 BOM** 的 UTF-16；GBK 这类本地编码要读就显式 `--encoding gbk`——
它同时**授权**去试 `probe` 判成 T4 的纯文本材料（仍限纯文本扩展名），读出来就把 `status` 改回 `ok`。
为什么不能自动猜：GBK 几乎能解**任何**字节对，拿它当判据等于把二进制当文本（与 `probe` 的 NUL / UTF-8 判据同一取向）。

**环境清单要显式**：新增依赖（Python 包）与**可选外部工具**（转换器）都要写成清单（如 `requirements.txt` + 一节"可选外部工具"）；
缺依赖报的错**要可执行**（说清装什么、或改走哪条路）—不许静默降级。

`extractor` 必须写清**具体走了哪条路**（`sdk:edsdk` / `vlm` / `ocr:tesseract` / `py:openpyxl`）—否则 §0 的"可追溯"就是空话。

**依赖清单（自包含侧的显式声明）**：

| 类别 | 清单 | 缺了怎么办 |
|---|---|---|
| **必须**（跑通主链） | `PyYAML`（已有）+ `python-docx` + `openpyxl` + `pdfplumber`（文本型 PDF） | 报**可执行**的错：装什么、装完重跑 |
| **可选**（增强） | `python-pptx`（演示稿）· `pytesseract` / `paddleocr`（图片 OCR） | 该格式降级为 T4 + 提示 |
| **外部工具**（通用工具，不是宿主技能） | LibreOffice / `soffice`（legacy 转换） | legacy 记 T4 + 提示「另存为 .docx」或「装 LibreOffice」 |
| **加速器**（宿主提供，**不许依赖**） | 本地 Office SDK · 多模态模型 | 探测不到就当没有，走自包含路径 |

**加速器探测判据**（「探测到才用」必须可执行）：

| 加速器 | 判据 | 判不出的默认 |
|---|---|---|
| 本地 Office SDK | `edsdk.py` **存在** 且 `list` 子命令**能通**（退出码 0 且有工具输出） | 视为不存在 |
| 多模态模型 | 由 AI **自报**「本会话能否直接看图」 | 视为不能 → 走 OCR / T4（**不许猜能看**） |
| **宿主模型直读文本** | 由 AI **自报**「本会话能否直接读文本」（`.md`/`.txt`/`.csv`/`.json`/`.yaml`/`.xml`/`.html`） | **视为能**（读文本是通则）；不能时走 `parse_text.py`（标准库，永远可用） |
| 外部转换器 | `soffice --version` 能通（PATH 或已知安装路径） | 视为没有 |

**探测结论要记账**（写进账本的 `extractor` / 材料卡片的解析路径栏）——不许**默默用**、也不许**默默不用**。


**批量后台读怎么调**（无人值守读 N 份材料）：用 `open_file file_path=<绝对路径>` 在**后台**打开（纯后台、无用户预览时 `file_id` 通常就是路径字符串），再用 `doc_*` / `sheet_*` / `slide_*` 的读工具取内容；**不要**用 `present_files`（那是给用户看预览面板的界面动作）。三条约束：
1. **路径字符串必须完全一致**：注册时用什么字符串，后续就得用什么（`./x.docx` — `/abs/x.docx`）⇒ 本流水线**统一用绝对路径**，且只允许一种分隔符写法。
2. **pool 会累积实例**：每打开一个文件就在 pool 里留一个实例；批量读要**分批**并显式释放（`close_file` 的 schema 单独确认）—SDK 文档里"不要主动 close"是针对"用户正在看"的场景。
3. **格式缺口**：`et` / `ett` / `dps` / `dpt` 不支持；含宏格式可打开但**宏不执行**（安全）。

四条硬要求：

1. **只读**：不许修改、移动、重命名材料。
2. **不抛裸异常**：失败要返回 `error` 文本（上游按"读不动"记账，见 §1.3）。
3. **不做业务判断**：不猜流程、不合并节点—判断在 AI 侧（与 `SKILL.md` "`scripts/` 只执行，不承载判断"同一条）。
4. **输出必须符合 §2 的 element 模型**，否则账本拒绝收（键封闭，见 §2.1）。

### 1.5 侦查（recon）：先排序、再假设、最后攻坚

**触发**：两条路——① 探测发现"异常"（体积 / element 预估 / 表数超阈值，或结构不像文档）；
② **流程表暴露的缺口**（§5.3 的定向取证）。第 ② 条才是常态：**侦查是 §5 那条循环的子程序**，
由缺口触发、被缺口限定范围，用完即走（"先落表、再回头读材料"的因果见 §5）。

**为什么需要**：真实材料里有**工具型文件**（如一张 sheet 就是一台计算器的测算表），能抽出几十万字符，却**没有过程步骤**。**先侦查，再决定解析深度。**

**侦查策略（八步，顺序不可换）**：

| 步 | 做什么 | 判据 / 产出 |
|---|---|---|
| 1 | 读**元数据** | `probe.py` 已给：文件名 / 类型（`kind`）/ 大小 / `sha256` / `mtime` / tier / probe |
| 2 | **难度排序** | 键 = `(tier 难度, bytes)`，`T1 < T2 < T3`；**同输入同顺序**（§2.2 可复现）。**分档只看 `bytes`**（见下"为什么不用 element 预估"） |
| 3 | **先读易的** | T1 且体积小 → 全量解析 |
| 4 | **分堆**（**不可跳过**） | 材料 → 流程归属假设（§3 版本关系 + §4 聚类）；纪律：**宁可多拆一条，不可错并两条** |
| 5 | **堆内拼流程** | 初步流程骨架（标 `⚠`） |
| 6 | **反推上下文缺口** | 由流程结构反推"**必然存在、但材料里没有**"的东西 → 缺口清单（这才是澄清申请的来源） |
| 7 | **攻坚难的** | T2（legacy）：需转换器；T3：视觉 / OCR。**每次只攻一层，产出必须落账本并带出处** |
| 8 | **循环** | **收敛判据与预算的口径只写在 §5.4**（硬漂移 0 且缺口清单空；每份材料攻坚上限 2 轮）；超预算落 `⚠?` 交用户—**不许无限重试** |

**为什么分档用 `bytes` 而不是"element 预估"**（2026-09-18 审计实测）：原先的"内容量"是 docx 数 body 块、
xlsx 数声明行数，**两个量纲被直接比大小**（174 行的表 vs 120 块的文档谁大？），而且一旦某份表读不动，
它的量就成 0、难度直接掉到"易"（崩溃与分档耦合）。`bytes` 跨格式可比、零依赖、不会因为读不动而失真；
结构缩样（段数 / 表数 / 大纲 / 子表尺寸）仍然照做，但只作**参考数字**进表里给人看，**不参与分档**。

**手段（按此优先级；「转图片」是最后的最后）**：

| # | 手段 | 怎么做 | 状态 |
|---|---|---|---|
| 0 | **抽取质量门**（**先过这道门**） | `textquality.py`：单字行占比 · 平均行长 · 坏字符率（替换字符/控制字符/私用区）· 单一字符占比 → `ok` 照收 · `noisy` 丢**纯碎片**元素 + 留下每条挂 `degraded` · `garbled` 该材料**不入账** + 建议处置；阈值在 `dictionary.yaml` 的 `material_quality` | 可用 |
| 1 | **结构缩样**（首选） | `recon.py`：**自包含**（`openpyxl` 读 sheet 尺寸、`python-docx` 读大纲）；宿主 Office SDK 若存在可读更全（公式 / 透视表计数）。**尽力而为**：读不了逐份记"结构读不了 + 原因"，**绝不让一份坏材料把整批带崩**；大纲**先数完再切**（表里写"共 K（列前 N）"，不许把截断数谎报成"共 N"） | 可用 |
| 2 | 转图片 → 视觉 | `render_pages.py`：PDF → 每页 PNG（**自包含**：pdfplumber + pypdfium2，实测 0.3~1.9 秒/页）→ AI 读图 → 填骨架 → `check` 校验；图片材料直接用原文件 | **PDF / 图片可用**；Office 系要转换器（本版不做，见 §8.2） |

**为什么"手段 0"必须排在"手段 1"前面**（实测，不是推演）：`probe` 说某份 PDF"有文本层"（`/Font` x161）、
`parse_pdf` 说"抽到 1563 字"——**两边都真**，可那条文本层是竖排 / 字距碎裂的水印碎片：整份 225 行里
140 行是单字行（62%），前 3 页 100%，首页抽出来是 `验 / 核 / 息 / 信 / 司 / 公 / 于 / 用 / 仅`。
**"读不动"是诚实的，"读出垃圾却当 `direct` 证据"是最坏的一种**——它污染唯一事实源，而没有任何仪器看得见。
所以：**T1/T2 抽出来的东西要先过质量门才算证据**；不过门的按上面的三级处置，**丢元素一律记账**
（不吭声地少几条，下游只会以为"这份材料本来就这么点内容"）。

**样本太小不判**（行数 < `min_lines`）：几行的材料没有统计意义，判了就是拿噪声当结论——
**宁可漏判，不可误判**（误判会把能读的材料判成读不动，那是把仪器的错算在材料头上）。

**假设必须落盘**（否则"循环"是黑箱，事后无法复现）：侦查结论写成表，**被推翻也要留痕**。

| 材料 | 假设角色 | 依据（数字 / 引文） | 档位 | 验证方式 | 状态 |
|---|---|---|---|---|---|
| `M05` | 技术要求（非流程） | 无「流程 / 审批」词，通篇参数表 | `⚠` | 读大纲看有无步骤章节 | 待验 |

**这张表落哪、谁填哪几格**（`scripts/recon.py`，与 §1.3 的"材料层补注"同一条分工线）：
- **脚本填**（`recon.py build`）：`材料 | 档位 | 难度 | 规模（依据数字） | 解析深度 | 走哪条路 | 读不动`
  ——全部**查表**得来（`tier` / `kind` / `bytes` 都是 `probe` 判的），**不猜语义**；
- **AI 填**：`假设角色（标 ⚠）| 依据 | 验证方式 | 状态`；
- **两列分开，别混一个轴**（审计：原先一格塞两个问题，下游无法机械消费）：
  - `解析深度` = 本节的**处置三选一**：`全量解析` / `只取摘要` / `不参与`；
  - `走哪条路` = §1.1 的档位映射（`直读` / `文本直读` / `PDF 文本抽取` / `转换器(soffice)` / `转图片→视觉` / `无 reader：T4 + 提示`）。
- **产物落成果根，默认名 `recon.md`**（登记在 `artifact.NON_TABLE_MD`，否则会被判"孤儿表"，§8.2）。
- **`材料卡片`（§3）不加「建议处置」列**：卡片是**标注层**（只装事实与推断），而"建议处置"是**过程性建议**
  ——原先本节写"写进材料卡片的「主题 / 含流程 / 建议处置」"，而 §3 的卡片契约里根本没有那一列（自相矛盾）。
  正确的关系是：**侦查结论落 `recon.md`，AI 据此把「主题 / 含流程」填进卡片**，卡片不照抄建议。
- **校验器**：`python scripts/recon.py check recon.md --materials materials.json`
  ——查材料一一对应、档位逐字等于材料层、`状态 ∈ {待验, 已验证, 已推翻}`、假设必带 `⚠`、
  `依据` / `验证方式` 非空，以及**`已推翻` 必须在假设角色里写成"曾记 X → 现记 Y"**（这就是"留痕"的落点）。
- **难度阈值住 `dictionary.yaml` 的 `recon:` 段**，且产物表头**打印本次用的阈值与输入指纹**——
  阈值是"人给的默认"，不是从某批样本反推的；打印出来才能事后复核（审计教训：原先的 `500` 正好落在
  某个 15 份样本的空档 (324, 606) 里，换一批材料边界就反复穿越）。

**产出与处置**：侦查结论落 **`recon.md`**（落成果根；AI 据此把「主题 / 含流程」填进材料卡片，见上面的分工表）；
处置三选一—`全量解析` / `只取摘要`（侦查结论 + 少量抽样，**不灌满账本**，这是 §2.4 降级该有的姿势）/
`不参与`（记 T4 + 理由，进 §4 的排除清单）。
**记账要求**：侦查结论算语义推断 → 标 `⚠`；**它凭以判断的结构数字（表数 / 行列数 / 大纲）要写进表里**，人能复核（对齐 §0 责任边界）。
**崩溃不外溢**：一份材料的结构读不了，只影响它自己那一行（记"结构读不了 + 原因"），
**不许让整批零产出**——审计实测过：原先一份坏 xlsx 就让 15 份材料一份都出不来、裸栈退 1。

## 2 L0 证据账本

### 2.1 element 模型

`evidence.json` 顶层：`{schema, task, materials[], elements[]}`。

**materials[]（材料层：一份材料一条）**

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `M01`…（§0：路径字典序） |
| `path` | 是 | 材料路径（原样，不改写） |
| `sha256` | 是 | 内容摘要—幂等与"材料换没换"的判据 |
| `bytes` | 是 | 字节数（探测先验之一） |
| `mtime` | 是 | 修改时间（ISO 8601 本地时区）—§3「替代」判据的**末位兜底**（前两位是正文日期、文件名日期） |
| `tier` | 是 | `T1`/`T2`/`T3`/`T4`（§1）；**不变式：`T1` ⇒ 必须有人认领**（§1.2） |
| `kind` | 是 | **机器可读的材料类型**，封闭枚举：`docx` / `xlsx` / `pptx` / `ole` / `pdf-text` / `pdf-scan` / `image` / `text` / `unknown`。**本仓"这是什么"的唯一判据源**——别处只许读它，不许按扩展名/魔数重判（§1.2） |
| `probe` | 是 | 档位依据（魔数 / 文本层密度 / …），人可核 |
| `status` | 是 | `ok` / `unreadable` / `skipped`。口径：**ok** = 这条材料的证据已在账本里（文本侧抽到了，或已由视觉侧产出）；**unreadable** = **读不动**（缺转换器 / 缺 OCR / 文件坏）——必须给 reason；**skipped** = **不参与**（T4：与流程无关、音视频…）——必须给 reason |
| `reason` | 视 status | 读不动 / 不参与的原因（**unreadable 与 skipped 必填**），要给**可执行**的话（装什么、或改走哪条路） |
| `extractor` | 视 status | 谁产的（插件名 / `soffice+py:docx` / `vlm`）。**由解析阶段的材料层补注写**（§1.4）：`probe` 只给档位，给不出这个 |

**谁写这三格**（唯一口径）：`probe.py` 给**初始值**（按档位：T1/T2/T3 → ok；T4 → unreadable + 依据）；
解析阶段用**补注**（§1.4）改它——补注是唯一入口，`ledger.py --notes` 校验（键封闭 / id 存在 / unreadable 必有 reason）
并**落完再校一次**。清点（§3）只读账本，**不重判**这三格。

**elements[]（证据层：只装"抽出来的东西"）**

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 稳定引用 id，规则见 §2.2 |
| `material_id` | 是 | `M01`… |
| `kind` | 是 | **封闭枚举**（见下） |
| `text` | 视 kind | 文字内容 |
| `rows` | 视 kind | 表格：二维数组（`table` / `sheet` 用） |
| `location` | 是 | 出处，见 §2.3 |
| `extractor` | 是 | 产出它的插件名（含 `vlm`） |
| `certainty` | 是 | `direct` / `inferred` 两值；T3 与任何机器猜测一律 `inferred` |
| `degraded` | 否 | **降级说明**（如 `quote 截断到 200 字`、`抽取质量有保留：单字行 62%…`）；没降级就**不写这个键** |

`kind` 初始枚举（**键封闭**：扩枚举必须先改本文）：

```text
heading  paragraph  list_item  table  figure  caption  code  sheet  cell
```

### 2.2 稳定 id 规则

```text
<material_id>#<kind 前缀><序号>        例：M03#p012（第 12 段）、M03#t7（第 7 张表）
```

三条硬要求：

1. **可复现**：同材料 + 同插件 + 同选项 ⇒ 同 id。**禁止**随机数、时间戳、不稳的集合迭代序。
2. **只增不改**：材料解析一次落一次；重解析要生成**新账本**并记录原因，不许就地改旧 id（否则 H10 的引用会集体失效）。
3. **顺序 = 文档阅读序**；表格内按 `行,列` 展开。

### 2.3 出处（location）格式

```json
{ "path": "材料路径", "page": 3, "sheet": null, "cell": null,
  "bbox": [x, y, w, h], "quote": "原文摘录（默认截断 200 字）" }
```

`quote` 的截断上限是为了控制账本体积；截断处必须留省略标记，不许无声变短。

### 2.4 写盘契约

- UTF-8、LF、缩进 2、`ensure_ascii=false`（中文不转义）。
- **幂等**：同输入两次 ⇒ 同字节（对齐现有"build 两次产物不变"的纪律）。
  **具名例外**：`extractor=vlm` 的元素**由 AI 识图产出**，同材料两次不会自动同字节（§1.3）——
  账本对**给定输入**仍然是确定的（同两份 JSON 两次同字节），不可复现的是"看图这一跳"这**上游**。
  所以 vlm 元素的 `certainty` 一律 `inferred`；要复现就得把那次识别的产物（那份 JSON）当输入留着。
- **键序固定**：按 §2.1 的字段序，不随解析顺序漂。
- **超上限先侦查、再决定**（§1.5）：处置为「只取摘要」时才缩 `quote` / 丢 `rows` 明细，并写明"哪份材料被降级"—**不许静默截断**，**也不许一上来就全量灌**。

### 2.5 L0 的对外承诺

**下游只许引用 `id`，不许回头读原文件。** 这是 L0 存在的全部意义：解析只做一次，之后的每一次引用都可机器复核。

### 2.6 与现有契约的接缝（一句话，细节留 §6）

现有"逐行回看出处"将从**人肉声明**升级为**可校验引用**：流程表「依据」列 = element id 列表；据此新增 **H10 证据完整性**（每个节点 ≥ 1 条依据；被引用的 id 必须存在；`⚠?` 必须挂在澄清申请上）。

## 3 L1 清点（材料卡片）

**输入**：`evidence.json`（材料层 + 证据层）。**输出**：`intake.md`—一份材料一行，**只标注、不新增真值**（落**成果根**，见 §0）。

| 材料 | 档位 | 主题 | 含流程 | 版本关系 | 读不动 | 依据 |
|---|---|---|---|---|---|---|
| `M07` 资质证明.pdf | T3 | 主体资质证明 | 否（无过程步骤） | 独立 | — | `vlm` 卡片证据 |

字段契约：

| 列 | 取值 | 规矩 |
|---|---|---|
| 材料 | `M##` + 文件名 | `M##` 一律**从账本抄**，不重编号 |
| 档位 | `T1`/`T2`/`T3`/`T4` | **从账本抄，不重判**（重判 = 双份真值，必漂） |
| 主题 | 一句话 | 语义推断 → 标 `⚠` |
| 含流程 | `是` / `否` / `不确定` | 三值封闭。**`是`/`否` 由 AI 判、必须给理由并标 `⚠`**（哪几份材料属于同一条流程是 AI 的职责，不是问用户的）；`不确定` 只留给"两种判法后果不同、且都说得通"，此时才进澄清申请 |
| 版本关系 | `独立` / `重复(M##)` / `互补(M##)` / `替代(M##)` / **`被替代(M##)`** / `无关(M##)` / **`不确定`** | **必须双向一致**，见下。后两个取值是本节的判据表要求、而取值列原先漏了的：`A 替代(B) ⇔ B 被替代(A)`；判不出写 `不确定`（不许猜）。**`—` 不是合法取值**——"没填"与"判不出"必须能分辨 |
| 读不动 | 原因 | 从账本的 `materials[].reason` 抄；空写 `—` |
| 依据 | element id 列表 | H10 核它 |

**版本关系的判据（可执行）**：

| 关系 | 成立条件 | 后果 |
|---|---|---|
| **重复** | 两份材料的 `sha256` 相同（内容逐字节相同） | 只保留一条（取 `M##` 小者），另一条标「副本」；**不许因此多出一条流程** |
| **互补** | 两材料主体/标的相同、内容不重叠冲突，且有「补充 / 附件 / 变更」类词或时间前后相接 | 归入**同一条流程**的材料集 |
| **替代** | 同名同标的、且版本号/日期更新的一份覆盖旧的一份。**日期取值优先级：正文里的签署/生效日期 → 文件名里的日期 → 文件系统 mtime**（mtime 最不可靠：复制一次就变） | 只采用新的；旧的记「未采用」 |
| 判不出 | — | **不确定 → 进澄清申请**（不许猜） |
| **无关** | 同目录但不共享主体/标的 | 各自成卡片，不进同一条流程 |

**判重只看 `sha256`，不看文件名与路径**：同名未必同内容（同名两版很常见），同内容未必同名（`补充协议.doc` 顶层一份、子目录一份）。

**双向一致**：`A 互补(M02)` 与 `M02 互补(M01)` 必须成对；`A 替代(B)` 与 `B 被替代(A)` 必须成对。单向声明按错处理—学 `§`/`parent` 双向一致的教训（H9 那条）。

三条纪律：

1. **清点不改账本**：发现材料缺失、读不动、可疑，只写卡片与澄清申请，**不许回头改 `evidence.json`**。
2. **不产生新真值**：卡片是账本的**标注层**；任何结论都要能指回材料级（`M##`）或片段级（element id）。
3. **顺序 = 材料路径字典序**（与 §0 的 `M01...` 同一口径）。
4. **拆解是 AI 的职责，不是问用户的问题**：哪几份材料属于同一条流程、要不要拆子流程，由 AI 判断并出草稿（标 `⚠`），用户只负责纠正。**澄清申请只装"推不出、且必须业务方拍板"的事**（口径冲突、外部约束），不装 AI 的专业判断。

**谁填哪几格**（`scripts/intake.py`，与 §1.5 的侦查器同一条分工线：**脚本只执行，不承载判断**）：

| 谁 | 格子 | 依据 |
|---|---|---|
| **脚本**（`intake.py build`） | 材料（`M##` + 文件名）· 档位 · 读不动（抄 `materials[].reason`）· **`重复` 关系** | 判重只看 `sha256`，是纯事实；档位/读不动只许抄，不许重判 |
| **AI** | 主题（标 `⚠`）· 含流程（`是`/`否` 标 `⚠` 并给理由）· 互补 / 替代 / 无关 · 依据 | 语义判断，脚本判不出 |

骨架里 AI 那几格写 `—`，`intake.py check` 会把"没填"当错——**"没填"与"填了"必须能分辨**，
否则一张空卡片也能过校验。校验器只查 §8 登记的那两条（**卡片与账本一致**：材料一一对应、档位逐字相等、
读不动逐字等于 `reason`；**版本关系双向一致**）+ 取值封闭 + "推断必须留痕"；
**不查 element id 存不存在**——那是 **H10.1** 的活（§6），在这里再写一份 id 提取就是两份真值。


## 4 L2 计划

**输入**：`intake.md`（材料卡片）+ `evidence.json`。**输出**：`plan.md`—回答**"做几张图、谁是谁的子、谁依赖谁、谁能并行"**（落**成果根**，见 §0）。

### 4.1 plan.md 的字段

**① 流程清单（一个流程一行）**

| 流程 | 角色 | 挂在 | 材料集 | 与其它流程 | 并行组 | 状态 |
|---|---|---|---|---|---|---|
| `F01` 采购申请 | 主 | — | `M02`、`M07` | — | `G1` | 可落表 |
| `F02` 供应商准入 | 主 | — | `M08`、`M09` | 共享(M08) F03 | `G1` | 可落表 |
| `F03` 结算付款 | 子 | `F01#07` | `M04`、`M08` | — | `G2` | 待澄清 |

| 列 | 取值 | 规矩 |
|---|---|---|
| 流程 | `F##` + 流程名 | `F##` 按"材料集里最小的 `M##`"排序（可复现）；**流程名 = 目录名**（允许中文） |
| 角色 | `主` / `子` | 子 = 被父流程的**一个节点展开**（甲） |
| 挂在 | `F0x#节点编号` / — | 只有子流程填；编号必须是**父流程表里的真实节点**（落表后由 H9 双向核） |
| 材料集 | `M##` 列表 | 每项必须在 `intake.md` 里存在（可机器核） |
| 与其它流程 | `接力(F0y)` / `共享(M##)` / — | 见 4.3。**嵌套（甲）由「角色 / 挂在」两列表达，本列只写乙 / 丙** |
| 并行组 | `G##` / — | 同组 = 互不依赖、可并行；**本版只记录、不调度**（§7） |
| 状态 | `可落表` / `待澄清` | `待澄清` = 还有 `⚠?` 没答 |

**② 澄清申请**（只装"推不出、且必须业务方拍板"的事，见 §3 纪律 4）

| 编号 | 问题 | 推荐答案 | 指向 |
|---|---|---|---|
| `Q1` | 两份同名文件哪份生效？ | 取正文日期较新者 | `M03`/`M04` |

**③ 排除清单**（从 `intake.md` 的"含流程 = 否"抄，含理由）

| 材料 | 理由 |
|---|---|
| `M15` | 主体资质证明，无过程步骤 |

### 4.2 拆解算法：材料 → 几条流程

按顺序跑，**前面判定的结果不许被后面推翻**：

| 步 | 做什么 | 判据 | 判不出怎么办 |
|---|---|---|---|
| 1 | 出种子 | 每份"含流程 = 是"的材料各出一个候选流程 | — |
| 2 | 合并（强） | `重复` / `互补` / `替代`（§3）→ **必并**（同一流程的材料集） | — |
| 3 | 合并（弱） | 两份材料共享 **起点事件 / 终点事件 / 交付物** 中的 ≥2 个 → 并 | 标 `⚠`，**不并**（保守） |
| 4 | 命名 | 主题短名（≤12 字） | 标 `⚠`，取材料名主干 |
| 5 | 定关系 | 见 4.3（甲 / 乙 / 丙） | 标 `⚠?`，进澄清申请 |
| 6 | 并行分组 | 互不依赖的流程同组 | — |

**保守原则**：**宁可多出一条流程，不可错并两条**—并错会让两张图的材料互相污染；拆多了只是多一次合并机会。

### 4.3 甲 / 乙 / 丙：三对关系怎么判

| 关系 | 判据（可执行） | 后果 |
|---|---|---|
| **甲 嵌套** | B 的**全部外部输入**来自 A 的**同一个节点 N**，且 B 的**全部输出**回到 N 的后继 | B 挂 `F0x#N` → 走 `⊞` 子表；`level` L1、`parent` 指回 A |
| **乙 接力** | A 的**结束事件** = B 的**开始事件**（A 的输出是 B 的输入），且**无回边** | 并列；描述里写"下游 → `F0y`"，**不画跨表边** |
| **丙 共享** | 两者共享同一**输入 / 依据 / 产出物**（同一 element），且互不包含 | 并列；记 `共享(M##)` |
| 都判不出 | — | 标 `⚠?`，进澄清申请 |

**为什么跨表不画边**：现有纪律是"**表自包含**"（跨表引用只写进描述），这样"每个节点恰好属于一张表"才成立，覆盖率与产物审核才判得准。甲 / 乙 / 丙 都不破坏这条。

### 4.4 计划与门禁的关系

- `plan.md` **不进机器门禁**（它没有唯一形态）。但**每一项都要能指回** `intake.md` / `evidence.json`。
- **可机器核的两条**：① 流程清单里的 `M##` 必须都在 `intake.md` 里；② 计划的流程数 = 实际生成的 `<流程名>/` 目录数。
- **改计划的顺序**：用户改了计划 → **先改 `plan.md`，再落流程表**。计划是"做几张"的事实源，流程表是"一张怎么做"的事实源（§0），两者不许互相代替。

### 4.5 拆解是 AI 的职责

`plan.md` 由 AI 产出，**每一行都算推断**（标 `⚠`）。按 §3 纪律 4：**只有"两种判法后果不同、且都说得通"才进澄清申请**；"拿不准但两种判法结果一样"不算不确定—直接判。

## 5 循环的发动机：漂移 → 缺口

**这一节管"过程"，其余各节管"工位"。** 真实过程是这样走完的：

```text
读目录树 → 直接读能直接读的 → 对读不了的做「假设」 → 形成对这批材料的整体理解
   → 先落一张流程表（带着假设与 ⚠?）→ 表自己暴露逻辑漂移
   → 漂移定位出上下文缺口 → 按缺口定向「撬开」文件（产物落盘）
   → 子代理读产物、只回摘要 → 据此修表 → 再审逻辑 → 循环
```

三条推论（它们解释了几处看起来"顺序奇怪"的规定）：

| 推论 | 它约束了什么 |
|---|---|
| **流程表是驱动者，侦查是它的子程序**（§1.5） | 先有表（哪怕整张都带假设），表发现问题，才去撬材料——**不是"等材料读干净了再归纳"** |
| **抽取量由缺口宽度决定，不由材料体积决定** | 没有具名消费者的材料**一个字都不必抽**。这条正面回答了 §1.5 开篇那类"能抽几十万字符却没有过程步骤"的工具型文件 |
| **直接读永远排在撬开前面** | 模型自己能读的格式（`.md` / `.csv` / `.txt` / `.json` …）先读；**脚本是给读不动的东西准备的手**，不是必经工位 |

### 5.1 漂移：定义与三个已知源

**漂移 = 表里的一条断言，与"我们已知的东西"不一致。**

"已知"只有三个来源，**没有第四个**：

| 源 | 它知道什么 | 产物 |
|---|---|---|
| **证据账本** | 这份材料读动没有 · 这条路是直取还是视觉推断 · 哪条被降级截断过 | `evidence.json`（§2） |
| **假设账** | 哪些结论是**猜的** · 猜的是什么 · 怎样才算验过 · 有没有被推翻 | `recon.md`（§1.5） |
| **表自身** | 结构（H1—H9 管得着的）+ 语义衔接（管不着的那些） | `flowtable.md` |

一句可执行的判据：**凡"已知它是猜的 / 已知它读不动 / 已知它被推翻 / 已知它是降级或视觉读数"，
而表里当事实用的，就是漂移。** 反过来说：**漂移的主因通常不是"材料不够"，而是"猜的忘了自己是猜的"**——
所以假设账不落盘，漂移就查不出来。

### 5.2 判据表：D1—D5

**五条全是硬档**：集合 / 枚举比对，机器确凿，可当结论。**这一版刻意没有软档判据**——
试过一条，实测精度太低，按"宁可漏判，不可误判"整条砍掉（理由与数字见本节末）。

| 号 | 判据 | 怎么机器判 | 它在防什么 |
|---|---|---|---|
| **D1** | **等级拔高**：依据指向的证据 `certainty=inferred`（`extractor=vlm`）或带 `degraded`，而节点没有 `⚠` 留痕 | 账本按 id 查 `certainty` / `degraded`，表里查 `⚠` | 把"我看到的 / 被截断的"当成"文件里逐字写着的"（§1.3 / §2.3 的纪律，此前**没有仪器**） |
| **D2** | **假设被推翻仍在用**：`recon.md` 里该假设 `状态 = 已推翻`，而表里仍有节点依据它 | 按 `M##` / 假设角色比对 | 表没跟着新认知走 |
| **D3** | **建立在读不动的材料上**：节点依据里的 `M##` 在账本里 `status = unreadable`（含质量门判 `garbled`） | 集合比对 | 这条断言的来源根本不存在 |
| **D4** | **含流程的材料零引用**：`intake.md` 里「含流程 = 是」的材料，表里没有任何节点引用它的 element | 集合比对 | 这份材料的信息**没进表**（漏读 / 读了没落表） |
| **D5** | **读了没用上**：某材料的 element 数 ≥ `coverage_min_elements`，而被表引用的比例 < `coverage_min_ratio` | 账本按 `material_id` 计数 + 表里的引用集合 | 这份材料**只被读了个开头**（或读了没落表） |

**出漂移还是出缺口**：D1—D3 是"**表写错了**"（→ 漂移清单）；D4 / D5 是"**还有东西没看**"
（→ 缺口清单）。后者不指责表，它**派活**——这正是 §5.3 那张表存在的理由。

**启用条件按输入可用性分档**（与 §6 的 H10 同一条纪律：**没有输入就不启用，绝不误伤合法的旧表**）：

| 判据 | 要什么输入 | 缺了怎么办 |
|---|---|---|
| D1 / D3 | 证据账本 | 跳过（不报错） |
| D2 | 证据账本 + 假设账 | 跳过 |
| D4 | 证据账本 + `intake.md` | 跳过 |
| D5 | 证据账本 + 流程表 + `drift:` 阈值 | 跳过 |

**D5 为什么要阈值**：覆盖比例是"读了多少用上多少"的读数，**不能用"比例低就是漂移"一刀切**——
一份 300 条元素的合订本，表里引 5 条可能正好够（该材料只有 5 处与流程有关）。所以它出的是**缺口**
（"这份材料还有 295 条没看，要不要看由 AI 判"），不是"表写错了"。阈值住 `dictionary.yaml` 的 `drift:` 段。

**为什么砍掉「输入输出接不上」（2026-09-18 实测，别再提它）**：原判据是"相邻两节点之间，
前驱「输出」与后继「输入」没有任何公共词"。在 `examples/workflow/flowtable.md` 上实测：
**14 条边报了 12 条**，逐条看过 **11 条是误报**，只有两类成因：

1. **回边**（`09→08`、`04→03`）：判断或自检发现问题就回上一环——前驱的产物本来就不是后继的输入；
2. **只是"顺序上的下一步"**（`01a→02`）：表里的 `下个节点` 表达的是**时序**，不是数据流，
   两列的措辞本来就不该有交集。

根因是**前提错了**：`输入` / `输出` 描述的是**单个节点自己的进出**，不是**一条边上的交接**；
拿它们比一条边，等于先假设"表里的边都是数据流"，而本仓的表不是这么建的。
**8% 精度的提示会让人去改 11 条本来对的表**，所以整条砍掉（登记在 `coding-spec` G14）。
真要判"中间少了一个环节"，得先让表能表达"**这条边传的是什么**"——那是字段契约的改动，不在本轮。

### 5.3 缺口清单：循环的燃料

**漂移说"哪里有毛病"，缺口说"缺什么、去哪找、怎么找"。** 后者才是 LLM 行动的依据。

脚本给**机器可判的那半**（哪份材料 · 它现在的状态 · 已抽几条 · 走哪条路）；
**"去要哪一片、值不值得要"是 AI 的判断**。

| 缺口 | 触发（D 号 / 节点） | 需要哪份材料 | 要哪一片 | 走哪条路（抄 `recon.md`） | 状态 |
|---|---|---|---|---|---|

- **三类来源**：① **漏读**（D4：含流程却零引用）② **猜的没验**（D2 / D3：断言建立在假设或读不动的材料上）
  ③ **读了没用上**（D5：覆盖比例过低，材料只被读了个开头）。
- **`要哪一片` 由 AI 填**（页 / 表 / 行区间 / 关键词）：这就是"渐进式批量"的抓手——
  **点名一小片，而不是把整份材料灌进上下文**。**取那一片的手是 `scripts/query.py`**：

      python scripts/query.py evidence.json --material M06 --grep 审批 --batch 5 --skip 10
      python scripts/query.py evidence.json --range pages=40-60 --range rows=100-200

  **它只查不抽**：在**已经落盘**的账本上按「哪份材料 / 哪一片 / 含哪个词」取一小批，回一小批 + **下一批的游标**。
  为什么不顺手把"抽取时收窄"也做了：那是两件事——收窄抽取省的是**解析代价**，本工具省的是**上下文窗口**；
  账本再大也躺在盘上，真正稀缺的是"这次给模型看几条"。所以**先能点名，再谈抽取时收窄**。
  坐标语法（`--range`，可重复）：`pages=A-B`（`location.page`，1 起）· `lines=A-B`（该材料内第 N 条元素，通用兜底）·
  `sheet=名`（xlsx 子表）· `rows=A-B`（**只裁显示**，表格类证据只打这几行——一张 10 万行的测算表是一条证据，
  不裁行等于把整张表倒进上下文）。`--grep` 是**朴素子串匹配**（正文 / 表格单元格 / 出处摘录），
  **不做分词、不做模糊**：判语义是 AI 的事（§0 责任边界）。
- **`走哪条路` 从 `recon.md` 抄，不另立一份**（§1.5"两列分开"已经算过这件事，重算是双份真值）。
- `状态 ∈ {待取证, 已取证, 已放弃}`；**`已放弃` 必须写理由**（不许静默放弃）。
- **澄清申请（§3 纪律 4 / §4.1②）是缺口清单里"必须业务方拍板"的那一类**，不另立第四类账。

### 5.4 三本账与收敛

"假设必须落盘"（§1.5）只是三本里的第一本。循环要能复现、要能不重复付费，三本都得留痕：

| 账 | 记什么 | 落点 |
|---|---|---|
| **假设账** | 哪些是猜的 · 猜什么 · 怎样才算验过 · 被推翻写成"曾记 X → 现记 Y" | `recon.md`（已有） |
| **证据账** | 撬开的产物与出处 · 等级 · 降级留痕 | `evidence.json`（已有） |
| **漂移账** | 每条漂移：发现 → 处置 → 依据 | `drift.md`（本节产物） |

**收敛判据**（口径只写在这里；§1.5 第 8 步引用它）：

```text
收敛 = 硬漂移 0 条  且  缺口清单空（澄清申请空 + 无取证缺口）
```

**预算**（防"越修越乱"）：

- **每份材料攻坚上限 2 轮**（§1.5 第 8 步）；
- **每一轮硬漂移数必须下降**：连续两轮不降就**停手**，把当前表 + 未决项交用户并标 `⚠?`——**不许无限重试**。

**漂移账的状态列（封闭）**：`已修`（改了表，重跑后该条消失）· `已解释`（判定不是漂移，**必须写理由**）·
`待验`（还没处理）——**收敛时不许有 `待验`**。

### 5.5 谁执行

| 谁 | 干什么 |
|---|---|
| 脚本 `scripts/drift.py` | 跑 D1—D5 · 生成缺口清单骨架 · 表头打印输入指纹、跳过的判据与阈值 |
| **AI** | 决定缺口补不补、**要哪一片** · 改成什么 · 修完复查（再跑 `check`） |
| **子代理** | 读撬开后落在盘上的产物，**只回摘要 + element id**——原文不进主上下文 |

**子代理摘要的三条纪律**（它是新的失真入口，别当成免费）：

1. **每个论断要能指回 element id**——否则摘要成为新的不可复现源（与 §2.4 的 vlm 具名例外同类）；
2. **只回摘要，不回原文**——原文在盘上，要复核按 id 回查；
3. **摘要搬运的是证据**：它引用的 id 照 D1 判等级，视觉来源照旧标 `⚠`。

**产物落点**：`drift.md` 落**成果根**，名字登记在 `artifact.NON_TABLE_MD`（否则被判"孤儿表"，§8.2）。

## 6 与现有契约的接缝：H10 证据完整性

**H10 是 L0 与现有结构校验（H1—H9）之间唯一的桥。**

**启用条件（最要紧的一条）**：**这次任务有账本**（`evidence.json`）时才启用。纯口头需求、示例表、自举树都没有账本 ⇒ **H10 跳过、不报错**。这条保证"新判据不误伤合法的旧表"。

| 判据 | 内容 | 为什么它可机器判 |
|---|---|---|
| H10.1 引用完整 | **任何产物**（流程表 / `intake.md` / `plan.md`）里出现的每个 element id 都必须在账本里存在 | id 是封闭语法（§2.2），可正则提取 + 集合比对 |

**H10 不要求「依据」必须是 element id**：用户完全可能凭口头需求落表，那时依据是散文。它只保证"**引用了就必须存在**"。

落地位置：`scripts/flowtable_check.py` 的三层校验内（与 H1—H9 同一套报错格式）。
启用前必须先在现有全部表上跑一遍确认 0 误伤——这是 H 系列历来的规矩。
