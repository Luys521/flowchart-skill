# NODE-AUDIT.md — 「有效节点」的原则在真材料上对过账没有

> 用途：原则写在 `references/material-to-nodes.md`，识别与清洗的判据写在 `PIPELINE-SPEC` §1.6。
> **写下来不等于被跑过**——这份文档只回答一件事：**逐条原则，在真材料上是有实例、有反例，还是空白。**
> 空白的那几条就是下一次开工的活；反例的那几条**不许修文档去迁就产物**（产物错就是产物错）。
> 记号：**成立** = 真材料上有实例 · **反例** = 原则成立而产物没做到 · **空白** = 从没行使过。

## 四、结论：三条该补的（按价值排）

1. **`⚠` 留痕归零**——13 处推断、0 处留痕，而"不确定显示在用户唯一会看的图上"是这套 SKILL 的核心承诺。
   补法**不需要新仪器**：`05 逐行回看内容出处` 那一圈，凡是"执行者含糊 / 产出两个 / 并行还是串行没明说"的，一律标 `⚠`
   （`⚠` = 有依据的推断，不问用户；只有"推不出且不同选法后果不同"才升 `⚠?`）。
2. **并行与子流程两条原则各 0 例**——不是原则错，是**没人试过**。材料信号已经摆在甲的表里：
   "与采购并行"（:57）、一份独立的踏勘施工流程（可作 `⊞` 子表）。
3. **尺子二（太薄）先落地**——它的两个样本就在丙的材料里，实现成本是 `probe`（或 `parse_pdf`）里几行 + `dictionary.yaml` 两个阈值；
   处置口径已写定在 §1.6（**建议转图片，不判读不动**）。

**反过来，这份对账也说明原则本身不是空中楼阁**：节点原则 **13 条**里 **8 条成立**
（6 条干净 + "有主体但弱" + "两遍自检只跑了正向"）· **3 处反例** · **2 处空白**（`⊞` / 视觉来源），
清洗那一半另有 **1 处空白**（尺子二）——
而且**3 处反例全部落在"机器核不了"的那半边**（留痕 · 并行 · 粒度），
与 `material-to-nodes.md` §8 的分工完全吻合：**H1—H9 管自洽（真表全绿），这份文档管合理（3 处不达标）**。
