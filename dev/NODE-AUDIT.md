# NODE-AUDIT.md — 「有效节点」的原则在真材料上对过账没有

> 用途：原则写在 `references/material-to-nodes.md`，识别与清洗的判据写在 `PIPELINE-SPEC` §1.6。
> **写下来不等于被跑过**——这份文档只回答两件事：
> ① **逐条原则，在真材料上是有实例、有反例，还是空白**（§一—§四）；
> ② **换一个没看过答案的执行者、照着规范读材料，能不能读出同一套节点**（§六—§七，盲读复现）。

> 记号：**成立** = 真材料上有实例 · **反例** = 原则成立而产物没做到 · **空白** = 从没行使过。

## 四、结论：该补的五条 —— **三条已补（都是通用能力），两条仍靠人**

1. **legacy 的自包含降级读法**（**本轮最值钱的一条，已实现**）：真 OLE 里按 UTF-16LE 抽文本 run，
   过质量门才入账、`degraded` 留痕、转换器在场仍优先。**它已经藏住了一个真差异**——
   原件写"每 **5MW** 或每半年"，用户转述件写"每 **10MW**"，而答案键用的是转述件；
   **原件进不了账本，"原件 vs 转述件"就永远比不了**（D 系列判据全都没得比）。
   落地与实测：`parse_legacy.runs_of` + 三道过滤防假正文；**读不动 5 份 → 1 份**、**119 条 `py:oletext` 证据**、夹具 **51**（§1.6）。
2. **`⚠` 留痕归零**（**仍靠人，没有也不该有仪器**）——13 处推断、0 处留痕，而"不确定显示在用户唯一会看的图上"是这套 SKILL 的核心承诺。
   补法**不需要新仪器**：`05 逐行回看内容出处` 那一圈，凡是"执行者含糊 / 产出两个 / 并行还是串行没明说"的，一律标 `⚠`
   （`⚠` = 有依据的推断，不问用户；只有"推不出且不同选法后果不同"才升 `⚠?`）。
   ——**反向证据在盲读里**：甲臂 49 个节点标了 **40 处 `⚠` / 4 处 `⚠?`**，说明这不是"做不到"，是"没人要求自己做到"。
3. **并行与子流程两条从没被真正行使**（**仍无实例**）——`⊞` **0 例**；全表唯一一处"并行"**只写在描述里**（图与表都是串行，见 §二）。
   材料信号已经摆在甲的表里："与采购并行"（:57）、一份独立的踏勘施工流程（可作 `⊞` 子表）。
4. **尺子二（太薄）**（**已实现**）——判据写定在 §1.6（两个量一起看），落在 `parse_pdf.thin_note` + `dictionary.yaml` 的 `pdf_text_layer:`，
   夹具 **53**（同元素数、只差字数的两份 PDF）；真样本双向验过（98 字/页判薄 · 548 / 988 字/页不判）。
   **顺带纠正了当初登记的错样本**：按"元素数"看出来的"薄"是假象，"一页一个 element"本来就是设计。
5. **依据的粒度**（**已实现**）：打块时遇表格行就断块——它不动节点集合，只把"依据指得到第几项"从**人话**变回**可引用的单元**；夹具 **52**。
   同一条路上还补了**质量门读数"丢前 / 丢完"并排打**（同一份材料 62% vs 37%，不并排打会让人以为读数说谎），也在夹具 **52**。

**反过来，这份对账也说明原则本身不是空中楼阁**：节点原则 **13 条**里 **8 条成立**
（6 条干净 + "有主体但弱" + "两遍自检只跑了正向"）· **3 处不达标**（`⚠` 0 处 / 一处两产出没拆 / 一条并行关系只活在散文里）· **2 处从没行使**（`⊞` / 视觉来源），
清洗那一半的 **3 处**（尺子二 · 依据粒度 · "丢前 / 丢后"读数口径）**都已补上**——
而且**3 处不达标全部落在"机器核不了"的那半边**（留痕 · 粒度 · 并行），
与 `material-to-nodes.md` §8 的分工完全吻合：**H1—H10 管自洽（真表全绿），这份文档管合理（3 处不达标）**。
**答案键是"三处同构"的**：用户给的节点表（43 行）、用户给的图（43 节点 / 50 边）、我转成的契约表（43 / 50）**逐字同构**——所以"节点集合"这件事**有唯一答案**，盲读复现才有对照物。
