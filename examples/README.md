# 样例

这里只有一个样例：`workflow/`。它既是**格式基准**，也是本 SKILL 唯一预置的范例。

> **本目录只放事实源**（人手写的 `flowtable.md`）。机器生成的产物住在 `dev/baseline/workflow/`
> ——那是本目录的**同构镜像**（同目录名 ⇒ 同产物名）。这样"改渲染器后产物逐字节不变"这条
> 安全网仍然成立，而人读的样例里不会混进 12 个生成文件（见 DECISIONS D-66）。

## 格式基准：`workflow/` ⭐

**SKILL 自举**——把**自身工作流**画成流程图（25 节点 / 34 边）。它描述一轮完整的活：**收到材料 → 建目录 → 读回现状 → 探测分档 → 侦查 → 解析入账 → 定范围 → 分堆 → 清点 → 计划（交用户审）→ 落表 → 校验 → 标注 → 问 → 出图 → 看 → 回流 → 对账 → 收敛 → 交付**；没收敛就回前面重来。九个带 `⊞` 的节点另有下钻子表（共 9 张子表 / 69 行）。
**写表、拿不准格式时先看它**：列怎么写、编号怎么编、描述怎么组织、`⚠` 推断留痕长什么样。
文档里的举例也全部取自它。它示范了九样最容易写错的东西：

| 示范什么 | 看哪一行 |
|---|---|
| **回环**（九条：`10→09`、`12→11`、`15→01`、`17→16`、`18→11`、`19→11`、`19→16`、`22→11`、`23→05`，其中 `15→01` 是回到起点的合法例外） | `10` / `12` / `15` / `17` / `18` / `19` / `22` / `23` |
| **一个节点三个出口**（三支各带标签） | `19 读回并分拣改动` |
| **判断节点的两个出口**（排斥，选一条走） | `07` / `10` / `12` / `14` / `17` / `18` / `21` / `22` |
| **插入编号**（`01a` 插在 `01` 与 `02` 之间，不必重编后面所有号） | `01a 建目录` |
| **`⚠` 一档推断留痕**（AI 按惯例补的，橙 + 疏虚线） | `01a` / `07` 节点描述 |
| **`⚠?` 二档必须拍板**（推不出、不同选法后果不同，红 + 密虚线） | `06` 节点描述 |
| **`★` 关键点**（只标漏看会出错的——主表 4 处 + 九张子表 13 处，全样例 17 / 94 行；通篇都标=没有重点） | `11` / `18` / `20` / `21` |
| **`行动所需时间`**（脚本工序填秒级时长，AI / 人工序留 `—`；**判断节点只画名称**，所以时间只填在会显示它的任务行上） | `01a` / `03` / `05` / `16` / `19` / `23` |
| **执行者与执行主体同档**（主体 `AI` 就填 `AI`；主体 `脚本` 才填具体脚本名；协作写 `双方共责`） | 全表；规则见 `templates/flowtable-template.md` 的「执行者」一行 |

> **它画的是"用这套 SKILL 干活的流程"，不是这份代码的函数地图。** 想看代码本身怎么工作，
> 那是另一棵树：`dev/tools/selfboot_gen.py` 生成的模块函数表（覆盖率 100%，规模现跑现取——
> 数字随代码增长，写死必漂，见 `dev/coding-spec.md` G7）。
> 两者名字里都带"自举"，但**一个画流程、一个画代码**——这正是本样例从 `self-demo` 改名为
> `workflow` 的原因（旧名与那棵树撞了"自举"二字）。

## 文件约定

每个流程一个目录，目录内文件名固定，可以直接当作工作目录使用：

```text
flowtable.md        事实源，AI 写、人改
checklist.md        自检报告（AI 推断项在此留痕）
workflow-flow.yaml           内部 DSL，脚本生成
workflow-flow.manifest.json  渲染契约（自检产出，供渲染后反查）
workflow-flow.html           评审版，悬浮看语义    ← 交付物①
workflow-flow.drawio         协作版，拖几何        ← 交付物②
workflow-flow.svg            朴素可编辑版，浏览器/Inkscape 直接开 ← 交付物③
workflow-index.md            层级索引（多张表时的构建顺序，派生量）
```

交付物① ② ③ 由 `build.py` 遍历**渲染器注册表**产出（`dev/ARCHITECTURE.md` 第九节 W5–W7）：
三份都从 `workflow-flow.yaml` 渲染、**互相零依赖**（svg 不是 html 的输入），
把带流程名的 `.html` 换成 `.drawio` / `.svg` 可直接单跑 `validate.py --artifact` 复核。

**刷新基线**（改了渲染器之后，必须让基线与代码对齐——**基线不进本目录**）：

```bash
# 1) 把事实源铺进基线目录（build 要求表与产物同目录，产物写在表旁边）
cp -r examples/workflow/. dev/baseline/workflow/
# 2) 只 build 主表——子表的 yaml/manifest 由它自动补齐为视图
#    （**不要逐表 build**：那会给每个子表多产 html/svg/index，旧基线里没有这三样）
python scripts/build.py <基线目录里那张临时表>
# 3) 删掉基线目录里的 flowtable.md（事实源的家在 examples/，基线只留产物）
find dev/baseline -name flowtable.md -delete
```

> 第 3 步是**全仓递归**的——`dev/baseline/self-boot/` 里那 38 张表**要留**（D-67：自举树连表带图进库）。
> 所以顺序是：**先重钉 workflow（含第 3 步），再把 `output/self-boot/` 整树镜像过去**。反了就会被删掉 38 张表。

> 第 2 步不写那张表的字面路径：它只是构建时的临时表、盘上不长期存在，写了会被面①的
> "文档引用的路径都必须存在"断言判成悬空引用。
